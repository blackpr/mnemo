# Adopt the store, build the governed gateway

No self-hosted, production-ready memory layer that spans Claude, Gemini, ChatGPT and the coding agents exists in October 2026, and the missing piece is not storage or retrieval but governance and attachment. The architecture question is largely settled: five recognizable families (self-edited tiered memory, LLM-extracted facts with reconciliation, bi-temporal knowledge graphs, raw history plus agentic search, and consolidating "memory OS" designs) all trade write-path cost against read-path cost, and the headline benchmarks that once separated them are now saturated, vendor-run and inside their own noise floor, so the honest case for an external layer is cost, horizon, portability and governance rather than accuracy. Of roughly twenty open projects, the "self-hostable" label is eroding at the top of the market: Zep Community Edition was deprecated in April 2025, Letta's Docker server is "no longer an actively maintained or supported" surface, Supermemory's self-hosted binary is built from a non-public codebase, and Mem0's open-source server has had graph memory and fact supersession ("Dream") removed. That leaves **Hindsight, Cognee, Honcho, MemOS, the Mem0 OSS server and OpenViking** as fully open servers with authentication and tenant isolation, with Hindsight the only one documenting a Kubernetes Helm deployment. Provider-native memory is a per-vendor silo everywhere; the Claude (March 2) and Gemini (March 26, 2026) "import" tools are paste-a-prompt, one-way affairs, and an independent July 2026 test of seven memory products found all seven fail import symmetry. The loudest documented demand, in Mem0's most-commented 2026 issues and on Hacker News, is for correctness and lifecycle (a 97.8% junk rate audit, time-blindness, missing CRUD, incomplete deletion, no decay) and for provenance, RBAC and audit that are "not part of a SaaS offering." The evidence therefore supports a **combine** strategy: adopt an open, Postgres-backed engine as a swappable retrieval component (Hindsight is the strongest fit, with Honcho and Cognee as alternates), and build the thin layer nobody ships: a single remote MCP endpoint plus an Anthropic memory-tool handler over one store, provenance and bi-temporal validity on every fact, scoped reads enforced on every path, verifiable deletion, a built-in evaluation harness with a full-context baseline, and a portable Markdown/JSONL export. Do not build another extractor, vector store or browser extension.

## Architectures have converged; production breaks on the write path, not retrieval

The March 2026 survey "Memory for Autonomous LLM Agents" formalizes agent memory as a write-manage-read loop and names five mechanism families (context-resident compression, retrieval-augmented stores, reflective self-improvement, hierarchical virtual context in the MemGPT style, and policy-learned management); it describes three production patterns and recommends starting with Pattern B, "context plus retrieval store," which it calls the "workhorse" behind most production agents, instrumenting heavily, and moving to learned control only when data justifies it ([arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)). The first systems-level characterization of these workloads, profiling ten systems across two benchmark suites, lands on the same headline: **design choices shift cost between the write and read paths** rather than eliminating it ([arXiv 2606.06448](https://arxiv.org/abs/2606.06448)). That framing explains the field's shape better than any leaderboard. Mem0-style extraction, Zep/Graphiti's temporal graph, Hindsight's retain-recall-reflect and Cognee's three-store design pay at write time with LLM calls; Letta's filesystem agent, Anthropic's memory tool and the "coding agent over files" approaches pay at read time with tool-use variance.

The write-path bill is concrete. In a September 2026 local run of a single 419-turn LoCoMo conversation, Mem0 2.1.0's extraction prompt was 33,653 characters (about 8,478 tokens) and was re-sent on every ingested turn, so input usage approached **ten million tokens before a single question was asked**; ingest cost 1.52 seconds per turn for Mem0, 3.65 seconds for Zep/Graphiti 0.30.2 and 0.37 seconds for Letta 0.11.7, while search p50 was 38 ms, 163 ms and 318 ms respectively ([Effloow](https://effloow.com/articles/mem0-zep-letta-agent-memory-latency-benchmark-2026)). Extraction is also brittle in ways that matter for a shared personal memory: a practitioner who tried Mem0 for an OpenClaw setup described the extracted store as "largely incomplete, invalid, inefficient and unhelpful sentences," with extraction breaking on irony and dates and confusing a changed trip booking, and the author of a competing store agreed those failure modes apply to any atomic-fact extractor ([HN comment](https://news.ycombinator.com/item?id=47770220)). The quality of what gets written then dominates downstream: in a nine-week longitudinal study, **weakly written facts failed 24% of the time versus 2% for others**, and a curated-map memory that led at three weeks fell from 96% to 72% recall of evicted content by nine weeks while a provenance-typed graph rose to 90% ([arXiv 2607.21962](https://arxiv.org/abs/2607.21962)). HaluMem's operation-level evaluation finds the same mechanism: errors introduced during extraction and updating accumulate and propagate to question answering ([arXiv 2511.03506](https://arxiv.org/pdf/2511.03506)).

The read-time alternative is more viable than it was. Letta showed in August 2025 that a GPT-4o-mini agent given only file tools (`grep`, `search_files`, `open`) over the raw conversation scored 74.0% on LoCoMo against Mem0's self-reported 68.5% graph variant, attributing the result to models being heavily trained on filesystem operations ([Letta](https://www.letta.com/blog/benchmarking-ai-agent-memory)). LongMemEval-V2 (May 2026) reports a coding-agent-over-files approach at 72.5% versus 48.5% for the strongest RAG baseline, with the caveat of high latency ([arXiv 2605.12493](https://arxiv.org/abs/2605.12493)). Anthropic's own API memory tool is built on this premise: it "operates client-side," Claude requests file operations under a `/memories` prefix and "your application runs them," so you control storage ([Claude Platform docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)). Anthropic reports that context editing alone cut token use 84% in a 100-turn evaluation and that memory plus context editing improved an agentic-search eval by 39% over baseline ([Claude blog](https://claude.com/blog/context-management)).

Long context has eroded the accuracy argument for external memory on short histories but not the economic one. A no-memory full-context baseline with gemini-3.1-flash-lite scored 80.7% on LoCoMo in October 2026, above the 2025 published figures for Zep (75.14) and Mem0 (66.88), albeit with different answering models ([braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)). Yet Chroma's "Context Rot" study of 18 models found performance "grows increasingly unreliable as input length grows," even on simple tasks ([Chroma](https://trychroma.com/research/context-rot)); Mem0's own BEAM scores fall from 64.1 at one million tokens to 48.6 at ten million ([Mem0](https://mem0.ai/blog/state-of-ai-agent-memory-2026)); MemoryArena task completion dropped from over 80% to about 45% when an active memory agent was replaced by a long-context-only baseline ([arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)); and the cost-aware MERIT benchmark concludes full replay "is never economical," with the best memory condition delivering 2.7 to 3.9 times the marginal utility per dollar ([arXiv 2609.05441](https://arxiv.org/abs/2609.05441)). The state of the art, then, is a hybrid: keep raw episodes as non-lossy provenance (as Graphiti does, per its [docs](https://help.getzep.com/graphiti/getting-started/overview)), layer extracted facts with bi-temporal validity on top, and let the answering model fall back to agentic search over the raw history when extraction is wrong.

What the 2026 literature treats as mandatory for production is remarkably consistent. Hindsight's consolidation analysis names four levers (importance, merge, decay, eviction), recommends recency-wins conflict resolution with explicit invalidation, "store facts, not turns," decay only where state changes are tracked, and eviction "as a compliance tool, not a performance tool" ([Hindsight](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)). The Zep/Graphiti bi-temporal model (`valid_at`/`invalid_at` for world time, `created_at`/`expired_at` for transaction time) has become the reference for supersession without deletion ([Zep](https://www.getzep.com/ai-agents/temporal-knowledge-graph/)). The multi-agent governance paper behind MemClaw names four failure modes ("unauthorized leakage," "stale propagation," "contradiction persistence," "provenance collapse"), reconstructed 100% of depth-four derivation chains with correct writer identity, and, importantly for anyone building this, found a sub-tenant scope bypass on direct GET-by-id and a pipeline-ordering bug where a synchronous near-duplicate gate rejected contradictory writes before the asynchronous contradiction detector saw them ([arXiv 2606.24535](https://arxiv.org/abs/2606.24535)). Memory poisoning is now a standard threat: MINJA achieved over 95% injection success through ordinary queries with no store access ([Red Sky Alliance](https://redskyalliance.org/xindustry/minja-memory-injection-attack)), and OWASP lists memory poisoning as ASI06 in its 2026 Agentic AI Top 10 ([Vectorize](https://vectorize.io/articles/ai-memory-poisoning)).

## Benchmarks no longer separate the leaders, so plan to run your own harness

On vendor-reported numbers the two canonical benchmarks are saturated: Mem0 claims LoCoMo 92.5 and LongMemEval-S 94.4, Zep 94.7 and 90.2, Hindsight 92.0 and 94.6, Honcho 89.9 and 90.4, MemOS 88.8 and 89.2 ([aiagentmemory.org leaderboard](https://aiagentmemory.org/articles/agent-memory-leaderboard/)). Those spreads sit inside the measured noise. Because LoCoMo's 1,540 questions cluster in ten conversations, the 95% confidence interval is about plus or minus 3.1 points and the minimum detectable difference between two systems is about 4.5 points; re-grading the same 1,540 answers with a different grading prompt moved a score from **55.8% to 81.4%**, and two independent audits found 6.4% to 7.0% of LoCoMo answer keys wrong or ambiguous ([braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)). Vectorize, itself a vendor, concedes that both benchmarks were designed for 32k-token contexts and now "mostly measure whether your LLM can read" ([Hindsight manifesto](https://hindsight.vectorize.io/blog/2026/03/23/agent-memory-benchmark)); Mem0's own guide admits public benchmarks "mostly grade retrieval" and rarely test writes, forgetting or consolidation ([Mem0](https://mem0.ai/blog/ai-memory-benchmarks-in-2026)).

The only same-harness public data reorders everything. OmniMemEval, run by MemOS's maker MemTensor with identical models, prompts and judge, scores MemOS 88.83 LoCoMo / 89.20 LME-S, Hindsight 81.99 / 72.20, Mem0 cloud 77.68 / 56.00, Letta 77.12 / 77.67, Supermemory 73.53 / 66.07 and Zep/Graphiti 63.83 / 79.80; Mem0 reports 94.4 on LongMemEval-S but scores 56.0 here, and only MemOS matches its own README ([aiagentmemory.org](https://aiagentmemory.org/articles/agent-memory-leaderboard/)). A competitor-run harness measured Mem0 at 73.8% LongMemEval against its 94.4% claim, and an independent paper reported 49.0% ([Mnemoverse](https://mnemoverse.com/docs/library/ai-memory-solutions-2026-q3)). Mem0's own users opened an issue in 2025 titled "Unable to reproduce locomo eval scores locally" ([GitHub #2800](https://github.com/mem0ai/mem0/issues/2800)). The 2025 Mem0-versus-Zep dispute, in which Zep's 84% LoCoMo claim was recounted to 75.14% after an adversarial-category accounting error, remains unresolved, and Dakera summarizes the 2026 state as "Mem0 contests Zep's methodology, and Zep disputes Mem0's" ([Dakera](https://dakera.ai/benchmark/)).

Two results reframe what a team should measure. MERIT found that agents acted on a correctly retrieved value only 55% of the time, that embedding retrieval was unstable on updated facts (0.30 to 0.95 across models), and that changing the memory implementation shifted task success by up to 60 points ([arXiv 2609.05441](https://arxiv.org/abs/2609.05441)). And one paper found QA scores and stored-memory quality diverge by an average of 16 points, meaning a high leaderboard score can sit atop a polluted store ([aiagentmemory.org](https://aiagentmemory.org/articles/agent-memory-leaderboard/)). The defensible evaluation, on which CoreDotToday and Vectorize converge, is a self-run harness on your own data with a full-context baseline using the same answering model, a published grader prompt, dropped questions disclosed, and cost and latency reported alongside accuracy; "if a memory system cannot beat it, its value lies in cost and latency" ([braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)). The benchmarks that currently discriminate between architectures are BEAM at 1M to 10M tokens, MemoryArena, HaluMem and multi-week horizon tests; LoCoMo and LongMemEval are regression tests.

Star counts are a weak maturity signal: Hindsight's repository was created on **October 30, 2025 and reached about 53,000 stars in under twelve months**, while Memary, a 2024 Hacker News favorite, has not been pushed since October 2024. The lock-in pattern among the best-known names is the single most important fact for a team worried about provider lock-in. Zep announced on April 2, 2025 that it would "stop maintaining and releasing Zep Community Edition," saying open-core "wasn't aligning well with our team's actual capabilities and values" ([Zep blog](https://www.getzep.com/blog/announcing-a-new-direction-for-zeps-open-source-strategy/)); Zep Cloud now carries SOC 2 Type II and HIPAA BAAs that the self-hosted Graphiti engine cannot ([Particula Tech](https://particula.tech/blog/agent-memory-frameworks-tested-mem0-zep-letta-cognee-2026)). Letta's documentation now lists Docker under "Deprecated" and its repository's `archive` branch "holds the retired Letta V1 API server," with active development moved to `letta-code` ([Letta README](https://github.com/letta-ai/letta)). Mem0's README concedes the managed platform has "proprietary optimizations not available in the open-source SDK" ([Mem0 README](https://github.com/mem0ai/mem0)), and the features it withholds are exactly the ones a serious self-hoster needs: a queryable graph, continuous supersession of outdated facts and duplicate merging, and organizations and projects ([Mem0 Platform vs OSS](https://docs.mem0.ai/platform/platform-vs-oss)). The standalone `mem0-mcp` repository was archived on March 24, 2026 and now points at a hosted endpoint at `mcp.mem0.ai` ([GitHub](https://github.com/mem0ai/mem0-mcp)). Mem0's open issues add self-hosting friction: a stale Docker Hub image for the OSS REST API, no semver-tagged images, and a Python client that cannot reach the documented OSS server ([GitHub issue search](https://api.github.com/search/issues?q=repo:mem0ai/mem0+is:issue+is:open+sort:reactions-%2B1-desc)). Mem0 raised $24M in October 2025 ([TechCrunch](https://techcrunch.com/2025/10/28/mem0-raises-24m-from-yc-peak-xv-and-basis-set-to-build-the-memory-layer-for-ai-apps/)); that capital funds the platform, not the OSS server.

Among the fully open servers, Hindsight is the most complete artifact on paper. It is MIT licensed, defaults to PostgreSQL with pgvector, lists "25+ providers" including OpenAI, Anthropic, Gemini, Groq, Bedrock, Ollama, LM Studio and llama.cpp, exposes REST plus Python, Node, Go and CLI clients, enables a per-bank MCP endpoint by default, offers an LLM wrapper that intercepts OpenAI or Anthropic clients to add automatic recall and retain, and documents Docker, Compose, Kubernetes via Helm and bare-metal pip ([Hindsight README](https://github.com/vectorize-io/hindsight)). Its paper reports 83.6% on LongMemEval with an open 20B-parameter backbone versus 39.0% for the same model with full context ([arXiv 2512.12818](https://arxiv.org/html/2512.12818v1)), which matters for a team that wants extraction on local or cheap models. Hindsight 1.0 and the "Memlake" object-storage engine shipped the week of October 15, 2026 ([Hindsight blog](https://hindsight.vectorize.io/blog/2026/10/15/hindsight-50k-stars)). The counterweights are that the project is under a year old, is backed by a vendor (Vectorize) that sells Hindsight Cloud with a 99.9% SLA, documents backups only for the cloud tier, and that its OmniMemEval LongMemEval score (72.2) is far below its self-reported 94.6 ([aiagentmemory.org](https://aiagentmemory.org/articles/agent-memory-leaderboard/)).

Cognee is the strongest alternative for a team that wants a knowledge graph. It "runs locally for free" with GLiNER and local embeddings, exposes `remember/recall/improve/forget`, ships Claude Code, Codex and OpenClaw plugins plus MCP and Python, TypeScript, Rust and REST clients, and defaults to multi-tenant authenticated API access ([Cognee README](https://github.com/topoteretes/cognee)). It raised a $7.5M seed in February 2026 with funds earmarked for a cloud platform, a Rust on-device engine and open source ([Cognee](https://www.cognee.ai/cognee-raises-seven-million-five-hundred-thousand-dollars-seed)). The caveats are that production Postgres-as-graph requires a licensed product, that it publishes no LongMemEval or LoCoMo score and its OmniMemEval LME-S result is 51.8 with 32,532 context tokens per LoCoMo query (the heaviest of any system measured), and that it has "No SOC 2 or HIPAA" ([Particula Tech](https://particula.tech/blog/agent-memory-frameworks-tested-mem0-zep-letta-cognee-2026)). Honcho is the most interesting conceptually for a "who the user is" layer: it models peers (humans and agents) as first-class, splits a synchronous storage API from an asynchronous insights "deriver," runs on Postgres with pgvector, and is AGPL-3.0 ([Honcho README](https://github.com/plastic-labs/honcho)); its defaults (OpenAI `gpt-5.4-mini`, auth off) require attention before exposure. MemOS is the only system whose self-reported numbers match a same-harness run, but that harness is its own ([aiagentmemory.org](https://aiagentmemory.org/articles/agent-memory-leaderboard/)), and it requires Neo4j plus Qdrant.

Two cross-cutting facts constrain adoption. First, **Postgres with pgvector is the de facto storage default** (Mem0 server, Honcho, Hindsight, Letta legacy, Cognee's optional path); Effloow's guidance is to "default to pgvector and add specialized memory only when it beats that baseline on your workload," and its capacity estimate for 10,000 users at 200 memories each is roughly 15 to 25 GB primary storage with 1,536-dimension vectors ([Effloow](https://effloow.com/articles/mem0-zep-letta-agent-memory-latency-benchmark-2026)). Second, no open project documents backups or observability as first-class self-hosted features; both are delegated to the database or appear only as cloud SLAs, and horizontal scaling is credibly documented only by Hindsight (Helm) and Cognee (distributed deploy templates). Under 500 concurrent agents, Mem0's abstraction added a "20-30% throughput reduction" against direct pgvector access with p99 around 220 ms ([DEV Community](https://dev.to/samuel_oakley/benchmarking-mem0aimem0-memory-overhead-and-recall-latency-under-concurrent-agent-workloads-10lg)), a reminder that the engine is a retrieval component rather than a source of truth.

## MCP reaches every client you use; provider memory stays siloed and import-only

Model Context Protocol is the one attachment point that reaches Claude, ChatGPT and Gemini simultaneously, and it is no longer an Anthropic asset. Anthropic donated MCP to the Linux Foundation's Agentic AI Foundation on December 9, 2025, co-founded with Block and OpenAI and supported by Google, Microsoft, AWS and Cloudflare, citing "more than 10,000 active public MCP servers" and adoption by ChatGPT, Cursor, Gemini, Microsoft Copilot and VS Code ([Anthropic](https://anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation)). The client matrix, updated October 20, 2026, has one critical asymmetry: Claude Desktop, Claude Code, Gemini CLI, Cursor and VS Code accept local stdio servers, but **ChatGPT reaches only remote servers over SSE or streamable HTTP**, requires Developer Mode on paid plans, and prompts on write actions; free Claude accounts are limited to one custom connector ([ContextBolt](https://contextbolt.com/blog/ai-tools-mcp-support/)). The Gemini consumer app's MCP support is undocumented in any source; the Gemini CLI is the reliable Google-side client. A self-hosted memory server must therefore expose remote streamable HTTP with OAuth to be universal. MCP standardizes access, not content: two clients writing to the same server will produce differently shaped memories unless the server enforces a schema.

Provider-native memory is uniformly a silo. The only portability that exists is prompt-based: Anthropic's import tool, launched March 2, 2026 alongside free-plan memory, asks the user to run a prompt in "your other AI service" that outputs entries formatted "[date saved, if available] - memory content" in a single code block, then paste it into Settings > Memory; imports are labelled "experimental," and the export path is to view memory in settings or "ask Claude in chat to write out memories verbatim," with no structured file format ([Anthropic Help](https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude)). Google followed on March 26, 2026 with a Gemini tool that likewise supplies a prompt to generate "a preferences summary" for pasting back ([MacRumors](https://www.macrumors.com/2026/03/26/gemini-import-tool/)). ChatGPT's data export ZIP contains conversations, not saved memories ([memx.app](https://memx.app/how-to/how-to-export-your-chatgpt-memory/)). An independent July 2026 test of seven products (ChatGPT, Claude, Claude Tag, Gemini, Cursor, Cognee, ByteRover) found all seven fail "import symmetry" and concluded that "AI memory portability, as a practical capability, does not exist" ([Stan Tyan](https://dev.to/stantyan/i-tested-7-ai-memory-products-for-portability-all-7-lock-you-in-31pm)). Microsoft is the one outlier in exportability, storing Microsoft 365 Copilot memories as `IPM.Contact` items in a hidden `CopilotMemory` mailbox folder reachable through eDiscovery and Graph ([Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory)), but that is an admin path, not a user or developer one.

On the developer side the three primitives are proprietary in interface and differ in where data lives. Anthropic's memory tool keeps data on your infrastructure by design ([Claude Platform docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)). OpenAI's Responses API offers `previous_response_id` chaining and Conversation objects but "doesn't describe any user-level or cross-conversation memory primitive" ([OpenAI docs](https://developers.openai.com/docs/guides/conversation-state)). Google's Vertex AI Agent Engine Memory Bank extracts and consolidates memories with Gemini inside GCP ([Google Cloud docs](https://docs.cloud.google.com/agent-builder/agent-engine/memory-bank/overview)), and a Redis re-measurement put it at 42.4% on LoCoMo against roughly 70% in the original paper ([braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)). The one provider memory that is already a self-owned, versionable artifact is Claude Code's: CLAUDE.md files and auto memory under `~/.claude/projects/<project>/memory/` are "plain markdown you can edit or delete at any time," are "machine-local," and `/init` already reads Cursor, Copilot, AGENTS.md, Windsurf and Cline rule files ([Claude Code docs](https://code.claude.com/docs/en/memory)). AGENTS.md is now a Linux Foundation project ([Linux Foundation](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)), which makes repository-level instruction memory the one piece that is already cross-vendor.

Reaching the web chat apps remains a patchwork. Mem0's free OpenMemory Chrome extension covers ChatGPT, Claude, Perplexity, Grok and Gemini and "works entirely in the browser, no server needed," but on Claude memory must be triggered manually with Ctrl+M ([Mem0 blog](https://mem0.ai/blog/introducing-the-openmemory-chrome-extension)); a dozen closed-source freemium extensions (MemoryPlugin, Vity, AI Context Flow) target the same sites, and roundups note they "only exist inside the browser, so they don't follow you into desktop apps or terminal coding agents" ([Plurality](https://plurality.network/blogs/how-to-sync-ai-memory-across-all-tools/)). No project surveyed ships a true OpenAI-compatible reverse proxy that injects and extracts memory transparently for arbitrary clients; the closest are Hindsight's client wrapper, LiteLLM's explicit `/v1/memory` store scoped per user and team ([LiteLLM docs](https://docs.litellm.ai/docs/proxy/memory)) and a Hindsight-LiteLLM recipe that injects memory through SDK-level callbacks ([Hindsight cookbook](https://hindsight.vectorize.io/cookbook/recipes/litellm-memory-demo)). Interchange formats are pre-standard: MacPaw's `.mem` bundle with canonical serialization, deletion tombstones with proof-of-reach and Ed25519 signing states it is "not yet independently implemented, neutrally governed, or widely adopted" ([MacPaw Research](https://research.macpaw.com/publications/portable-memory)); the W3C AI Agent Memory Interoperability Community Group launched June 3, 2026 with 36 participants and twelve-month deliverables that are reports, not Recommendations ([W3C](https://www.w3.org/community/ai-agent-memory-interop/)). The regulatory tailwind is real but indirect: the EU Data Act bans switching charges for data processing services from January 12, 2027 ([Latham & Watkins](https://www.lw.com/en/insights/2025/08/EU-Data-Act-Significant-New-Switching-Requirements-Due-to-Take-Effect-for-Data-Processing-Services)), though no regulator has yet said chatbot memory is covered.

The team's thesis that "the provider that knows us best will win" is shared by both sides of the market. Sam Altman described building "infinite, perfect memory" ([CMSWire](https://www.cmswire.com/digital-experience/i-spoke-with-sam-altman-what-openais-future-actually-looks-like/)); Activant Research calls accumulated memory "one of the last real switching costs in enterprise software" and argues that memory layers are "shifting the record into customer-owned databases," with the thesis breaking only if "a lab shipping fully portable, cross-vendor memory" happens ([Activant](https://www.activantcapital.com/research/the-memory-moat)). The March 2026 import race is itself evidence that providers treat memory as a switching cost worth attacking, but because every tool is import-only, each re-locks the user in a new silo.

## The open niche is governed memory infrastructure, not another store

Demand is documented most precisely in Mem0's issue tracker, because Mem0 is the most-used open project. Its most-commented 2026 issues are all about correctness and lifecycle rather than integrations. An audit of **10,134 Mem0 entries found 97.8% were junk**: "we had to read 10,134 entries to find 38 clean ones" ([GitHub #4573](https://github.com/mem0ai/mem0/issues/4573)). A 54-comment open issue documents workarounds for "time-blindness, semantic conflicts, and missing CRUD," noting that "vector search returns them sorted by similarity rather than recency" ([GitHub #5352](https://github.com/mem0ai/mem0/issues/5352)). Others cover ADD-only extraction surfacing stale and contradictory facts after the v3 upgrade ([GitHub #4956](https://github.com/mem0ai/mem0/issues/4956)), silent memory loss when batch embedding partially fails ([GitHub #5245](https://github.com/mem0ai/mem0/issues/5245)), `delete_all()` leaving session messages that are re-sent to the LLM, "for someone who asked to have their data removed, that's the part that matters" ([GitHub #7452](https://github.com/mem0ai/mem0/issues/7452)), no expiration or decay mechanism ([GitHub #5330](https://github.com/mem0ai/mem0/issues/5330)), and a proposal for a faithfulness check before write because the system "has no notion of whose fact it is" ([GitHub #7283](https://github.com/mem0ai/mem0/issues/7283)). On Hacker News, an engineer evaluating enterprise agent memory found "none that took care of memory provenance, contradictions, RBAC, filtering, etc., that were not part of a SaaS offering" and wanted "actual infrastructure (consistency, audit, retention) rather than another harness feature" ([HN 48021715](https://news.ycombinator.com/item?id=48021715)); another summarized the status quo as "Everyone's building the same workarounds. CLAUDE.md files. Handoff docs. Learnings folders." ([HN comment search](https://hn.algolia.com/api/v1/search?query=%22memory%20layer%22%20agents&tags=comment&hitsPerPage=50)).

The supply side shows where the crowding is and where it is not. Cross-tool memory for coding agents is crowded at the hobby level: mcpservers.org lists **324 "Memory" MCP servers** ([mcpservers.org](https://mcpservers.org/category/memory)), and 2025 to 2026 Show HN launches marketed purely as "beats Mem0 on LoCoMo" mostly drew one to four points and zero or one comments ([HN Algolia](https://hn.algolia.com/api/v1/search?query=mem0&tags=story&hitsPerPage=30)). The native tools are deliberately siloed (Claude Code auto memory is machine-local, Codex Memories are not shared with other clients), and the cross-tool "local SQLite MCP server" is a low-moat niche. By contrast, memory evaluation and observability is nearly empty as a product category: no dedicated tool surfaced for tracing what was written, retrieved and used, despite benchmark disputes, unreproducible scores and MERIT's 55% act-on-retrieval rate. The governance bar is currently set by a hosted product rather than open source: Anthropic's Claude Managed Agents memory (public beta April 23, 2026) gives every change an immutable memory version, a redact endpoint that scrubs content from historical versions "for compliance workflows," and read-only mounts ([BuildFastWithAI](https://www.buildfastwithai.com/blogs/claude-managed-agents-memory-2026)). The compliance literature converges on a tiered design (session context, extracted facts, pseudonymized audit records, model-influence records), tenant isolation enforced at the query layer with a workspace ID on every operation, and a deletion workflow that inventories, deletes, verifies zero results and issues a receipt ([Chanl](https://www.channel.tel/blog/gdpr-delete-eu-ai-act-keep-memory-compliance)); an August 2026 local-memory design distinguishes "deleted" from "provably deleted" by writing an erasure record to a hash-chained audit log before deleting and failing closed if the log write fails ([arXiv 2608.08253](https://arxiv.org/pdf/2608.08253)).

Capital flows confirm which slice is defensible. Dedicated memory-layer vendors are seed to Series A scale (Mem0 $24M, Letta $10M, Cognee $7.5M, Supermemory roughly $3M), while the one large 2026 round, **Engram's $98M at a $600M valuation**, went to a company that trains per-customer models to pre-study an organization's documents, claiming up to 100x fewer tokens ([CNBC](https://www.cnbc.com/2026/06/23/ai-memory-startup-focused-on-cutting-token-costs-raises-98-million.html)). The Deep Feed's June 2026 analysis argues that user-level personalization memory is the slice most exposed to absorption by OpenAI, Anthropic and Google (who bundled memory for free in spring 2026), while typed business knowledge and customer-specific verification are harder to absorb and enterprises may be reluctant to let a model provider hold their business-knowledge graph ([The Deep Feed](https://www.thedeepfeed.ai/posts/2026-06-12-agent-memory-seed-wave/)). An "Ask HN: Who is the main customer for Mem0/Supermemory, why they pay?" drew one point and zero comments ([HN 46004834](https://news.ycombinator.com/item?id=46004834)), consistent with standalone personalization memory having unproven monetization. Arize's framing of when a dedicated layer pays off, cross-session persistence, sharing memory across agents, and independent retention and deletion policies ([Arize](https://arize.com/ai-memory/)), is precisely the set of properties provider-native memory does not offer across vendors.

Putting demand, supply and capital together, the genuinely open niche is not a new memory algorithm. It is **provider-agnostic memory as governed infrastructure**: a self-hosted layer whose differentiators are provenance on every fact (source episode, writer identity, extraction model version, confirmation state), bi-temporal validity with explicit invalidation, scoped reads enforced on every access path, verifiable deletion across vectors, facts, caches and logs, a built-in reproducible evaluation harness with a full-context baseline, write and read traces, and a single attachment surface (remote MCP with OAuth plus an Anthropic memory-tool handler) over one store with a portable export. Every one of those items maps to a cited complaint or a cited production finding, and no open project ships the set.

## Recommendation: combine, by adopting a Postgres engine and building the governed gateway

The decision for a small engineering team is to combine, not to build from scratch and not to adopt a single product wholesale. Adopt an open, Postgres-backed engine for storage, extraction and retrieval, treat it as a swappable component behind your own data model, and build the thin governance and attachment layer that the evidence shows is missing. Each element of the recommendation is separated below into what the sources establish and what is inferred from them.

Two honest limits apply. First, the team's stated goal of one memory shared across "Claude, Gemini, others" is fully achievable for Claude Desktop, Claude Code, Gemini CLI, Cursor, VS Code and any API-driven agent, partially achievable for ChatGPT (paid Developer Mode, remote server, write confirmations) and not reliably achievable for the Gemini consumer app, whose MCP support no source documents. Second, the research corpus here is Hacker News, GitHub and vendor documentation; Reddit and Discord were unreachable, Hindsight's quality in the wild is attested only by its vendor, and the sunsetting of Letta's server rests on a third-party analysis plus README language. A two-week spike that stands up Hindsight and Honcho side by side on the team's own transcripts, with a pgvector-plus-full-context baseline and the CoreDotToday checklist (same answering model, published grader prompt, minimum detectable difference, cost and latency), would resolve the engine choice with more confidence than any public number can.

## Conclusion

The lock-in the team fears is real, but it does not come from any provider having a better memory algorithm; it comes from providers holding the record. The 2026 evidence shows that algorithms have commoditized (five families, saturated benchmarks, Postgres as the default substrate) while the record itself has become the contested asset: the labs ship one-way import tools, the best-known open servers retreat behind clouds, and the funding goes to companies that bind memory to proprietary data or model weights. That inverts the usual build-versus-buy calculus. The valuable thing to own is not a retrieval engine but the system of record, its schema, its provenance and its deletion semantics, with any engine mounted beneath it as a replaceable retrieval component. A team that holds the episode log and fact store in its own Postgres, surfaces it through MCP and the Anthropic memory tool, and can regenerate any provider's import format from it has already escaped the "knows you best" trap regardless of which model it uses next year.

The second implication is that evaluation is a product feature, not a research chore. Every public number in this space is vendor-run and inside the noise, and the one same-harness table reorders the field by 15 to 40 points. A layer that ships with its own harness, a full-context baseline and write/read traces is the only kind whose claims the team, or anyone else, can verify, and it would occupy a category that is still empty. If the project is ever released, that transparency, together with a credible "we will not sunset the self-hosted server" commitment of the kind Zep and Letta failed to keep, is the differentiator the market has shown it will pay attention to.
