## ChatGPT (web, desktop, mobile): can it use a custom remote MCP server, on which plans, with what transport, auth and write behaviour?

### Takeaway
Yes, on the web, through developer mode / "Add custom MCP server" (now under **Plugins**). Auth is OAuth 2.1 + PKCE with CIMD (preferred), DCR or a static client, or no auth. Static API keys and custom headers are **not** supported, so mem's current bearer key will not work. Write tools work, with a per-call confirmation that can be remembered for one conversation. Plans are the weak point. The help center describes full read+write MCP for **Business and Enterprise/Edu**, and **Pro limited to read/fetch**. **Plus** is contested. The server must be reachable from OpenAI's cloud (published egress IPs, optional mTLS), or through OpenAI's "Secure MCP Tunnel".

### Cited Findings
**Plans and platforms**
- Full MCP (including write/modify actions) is in beta for Business and Enterprise/Edu. "Pro users can connect MCPs with read/fetch permissions in developer mode"; full MCP is "only available to Business and Enterprise/Edu users, currently"; Pro users can build apps with the Apps SDK. Admins/owners enable developer mode in workspace settings and can publish custom apps to their org. (help-center extract) [official, wording varies by version] — [OpenAI Help: Developer mode and MCP apps](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt); [variant slug](https://help.openai.com/en/articles/12584461-developer-mode-apps-and-full-mcp-connectors-in-chatgpt-beta)
- MCP apps "are not available on mobile and are web only" (help-center extract) — [OpenAI Help](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt). The current developer guide also scopes custom MCP servers to "ChatGPT on the web" — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server) [official, undated]
- Developer docs don't name plans. They say only "Account and workspace policies apply", and that workspace permissions and security restrictions, including Lockdown, apply — [OpenAI: Connect from ChatGPT](https://developers.openai.com/apps-sdk/deploy/connect-chatgpt); [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server)
- **Conflict on Plus:** Hatchable (updated 2026-08-21) lists developer mode for Plus, Pro, Business, Enterprise and Edu, and not Free; on Business/Enterprise a workspace owner must enable it first [secondary] — [Hatchable](https://hatchable.com/articles/how-to-add-an-mcp-server-to-chatgpt). Tempreon says the help center doesn't address Plus while the developer docs list Plus as eligible, and advises treating writes on Plus as untested [secondary] — [Tempreon](https://tempreon.com/guides/add-mcp-server-to-chatgpt). Peliqan says developer mode moved to workspace plans, so Free/Plus/Pro cannot create a custom connector, and Business admins cannot enable it per member [secondary] — [Peliqan](https://peliqan.io/blog/chatgpt-mcp/)
- A community report says Business workspace owners saw developer mode locked as an "Enterprise" feature and write calls blocked. Anecdotal and disputed in the thread — [OpenAI Community](https://community.openai.com/t/write-actions-blocked-on-custom-mcp-server-business-plan-workspace-developer-mode-unavailable-at-workspace-level/1384381) [secondary]
- July 2026: apps were renamed "plugins", and the app directory was folded into a plugin directory shared with Codex. Menus may say "Apps" or "Plugins" [secondary] — [Hatchable](https://hatchable.com/articles/how-to-add-an-mcp-server-to-chatgpt); [Wikipedia: ChatGPT](https://en.wikipedia.org/wiki/ChatGPT). The current official flow is ChatGPT Plugins (chatgpt.com/plugins) → "+" → "Add custom MCP server" → URL and auth → accept the risk warning → "Create as a plugin" → install — [OpenAI: Building MCP servers](https://developers.openai.com/api/docs/mcp); [OpenAI: Connect from ChatGPT](https://developers.openai.com/apps-sdk/deploy/connect-chatgpt)
- Desktop: the Codex docs say the ChatGPT **desktop app**, Codex CLI and the IDE extension share one local MCP configuration, and that ChatGPT web doesn't read local Codex config files — [OpenAI Codex docs: MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) (redirect target of developers.openai.com/codex/mcp) [official, undated]

**Transport and network origin**
- Supported connection types: "Server-Sent Events (SSE) and streaming HTTP", plus a **Secure MCP Tunnel** option — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server). Remote HTTPS only; local stdio is not supported [secondary] — [Hatchable](https://hatchable.com/articles/how-to-add-an-mcp-server-to-chatgpt)
- Calls originate from OpenAI's infrastructure. Servers can allowlist ChatGPT's published egress IP ranges, and can validate an OpenAI-managed mTLS client certificate (SAN `mtls.prod.connectors.openai.com`, chaining to the OpenAI Connectors mTLS intermediate CA) — [OpenAI Apps SDK: Authentication](https://developers.openai.com/apps-sdk/build/auth)

**Auth**
- OAuth 2.1 authorization code + PKCE (the AS must advertise `S256`). Client registration options: **CIMD preferred** (`client_id_metadata_document_supported: true`; client IDs `https://chatgpt.com/oauth/client.json` or `https://chatgpt.com/oauth/{callback_id}/client.json`; token auth `none` or `private_key_jwt`, with ChatGPT's JWKS at `/oauth/jwks.json`), **DCR** (registers once per server connection and reuses the client), or **predefined clients** (`none`, `client_secret_post`, `client_secret_basic`) — [OpenAI Apps SDK: Authentication](https://developers.openai.com/apps-sdk/build/auth)
- Order of preference: static credentials if provided, otherwise CIMD if the AS supports it and the creator selects it, otherwise DCR. Mixed mode is allowed: initialize/list-tools without auth, with each tool's `securitySchemes` (`noauth` / `oauth2`) deciding — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server)
- **Not supported:** client-credentials/service-account/JWT-bearer grants, **custom API keys**, customer mTLS certs — [OpenAI Apps SDK: Authentication](https://developers.openai.com/apps-sdk/build/auth)
- Redirect URIs: `https://chatgpt.com/connector_platform_oauth_redirect` (stable, when the AS supports RFC 9207 `iss`), otherwise `https://chatgpt.com/connector/oauth/{callback_id}`. The server's management page shows the exact URI to allowlist — [OpenAI Apps SDK: Authentication](https://developers.openai.com/apps-sdk/build/auth)
- Required server metadata: `/.well-known/oauth-protected-resource` (or `resource_metadata` in a 401 `WWW-Authenticate`) with `resource` and `authorization_servers`; AS metadata at `/.well-known/oauth-authorization-server` or `openid-configuration`; the `resource` parameter is sent on authorize and token requests and should become the token `aud`; the server must verify `iss`, `aud`, `exp`/`nbf` and scopes on every request. Tool-level auth prompts are triggered by a tool error carrying `_meta["mcp/www_authenticate"]` — [OpenAI Apps SDK: Authentication](https://developers.openai.com/apps-sdk/build/auth)

**Write tools, confirmations, modes**
- "Write actions require confirmation by default". Users can remember approve/deny per tool **within a conversation**; new conversations, and refreshed ones, prompt again. Full JSON tool inputs and outputs are inspectable — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server)
- "ChatGPT currently requires manual confirmation in any conversation before write actions", and a write can occur even if the server marked the tool read-only — [OpenAI: Building MCP servers](https://developers.openai.com/api/docs/mcp)
- ChatGPT may ask for confirmation depending on app permissions, context and impact, and some risky actions may be blocked outright (help-center extract) — [OpenAI Help](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)
- **Deep research** can use custom apps for **read/fetch only, not writes**. **Agent mode will not use custom apps** (help-center extract) — [OpenAI Help](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt); [Connected apps in ChatGPT](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt)
- For deep research and company knowledge, a server should implement read-only `search(query) → {results:[{id,title,url}]}` and `fetch(id) → {id,title,text,url,metadata?}`, returned as `structuredContent` plus a JSON string in `content`. Citations need a non-empty `url` — [OpenAI: Building MCP servers](https://developers.openai.com/api/docs/mcp). Ordinary custom MCP plugins don't need search/fetch, and any tools (writes included) are available subject to confirmation — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server)

**Instructions, annotations, automatic use**
- MCP server `instructions` are honoured. Keep the first 512 characters self-contained; refreshing the app pulls updated instructions — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server)
- `readOnlyHint` is respected. Tools **without** it are treated as write actions (confirmation) — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server). The Apps SDK reference lists `readOnlyHint`, `destructiveHint` and `openWorldHint` as **required** on tool descriptors (`idempotentHint` optional). `destructiveHint` is what triggers an explicit approval prompt, and the hints affect only presentation, so servers must still enforce authorization — [OpenAI Apps SDK reference](https://developers.openai.com/apps-sdk/reference)
- Invocation: "type `@` in the prompt box and select" the installed plugin. Docs describe explicit per-conversation selection, not automatic use in all chats, and suggest naming the app and tool in prompts — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server); [OpenAI: Connect from ChatGPT](https://developers.openai.com/apps-sdk/deploy/connect-chatgpt). Developer-mode connectors are chosen per chat from the + menu [secondary] — [Hatchable](https://hatchable.com/articles/how-to-add-an-mcp-server-to-chatgpt)

### Inferences
- mem's static bearer API key cannot be used with ChatGPT. OAuth is required (or no auth, which is unacceptable for a personal memory). The cheapest ChatGPT-compatible path is PKCE S256 + CIMD or DCR, RFC 9207 `iss` in authorization responses (unlocks the stable redirect URI), protected-resource metadata, and `aud`-bound tokens.
- mem must be publicly reachable over HTTPS from OpenAI's cloud, or use the Secure MCP Tunnel (details not researched). It can lock down by OpenAI egress IPs and/or the mTLS client cert.
- Annotate `recall` and `list_facts` with `readOnlyHint: true` (and `destructiveHint: false`, `openWorldHint: false`) to avoid confirmation prompts. `retain`, `confirm_fact` and `dispute_fact` will prompt on every call unless "remembered" for that conversation. Consider `destructiveHint: false` on them, since the Apps SDK says destructiveHint drives the prompt, but the custom-server guide says anything not read-only is confirmed anyway.
- If the owner is on personal Plus/Pro rather than Business, writes (`retain` etc.) may be unavailable: the help center explicitly gives Pro read/fetch only. Test on the owner's actual plan before relying on ChatGPT as a writer.
- Deep research would only use mem if it exposed `search`/`fetch`-shaped tools. Thin aliases over `recall`/`list_facts` would be needed.
- Because selection is per conversation via `@`, ChatGPT will not consult mem in every chat by default. Server `instructions` help only once the plugin is in play.

### Gaps
- The exact current plan matrix (especially **Plus**, and whether Pro has since gained writes) could not be read from help.openai.com (403); third-party sources conflict.
- No confirmation of whether custom MCP plugins added on the web work in the ChatGPT **mobile** or **desktop** apps after the July 2026 plugins change. The help-center extract says web only.
- Secure MCP Tunnel: setup, plan availability and whether it removes the public-endpoint need are undocumented in the pages read.
- No regional restrictions found in any page read.

## ChatGPT built-in memory: what it stores, view/edit/delete, and every import/export path

### Takeaway
ChatGPT has **saved memories** plus **reference chat history**, with a memory summary in Settings → Personalization. Users can view and delete entries, and edits are increasingly done by asking ChatGPT. There is **no official import feature, no memory API**, and the standard account data export reportedly does **not** include saved memories. The only routes in are telling ChatGPT to remember things in chat. The routes out are copying the memory summary, or asking ChatGPT to dump what it knows.

### Cited Findings
- Two memory types: saved memories are details ChatGPT is asked to keep, stored separately from chat history. Deleting a chat does not delete a saved memory derived from it, and vice versa. Turning off "Reference saved memories" also turns off "Reference chat history". Turning off chat-history reference schedules remembered chat information for deletion within 30 days (help-center extract) — [OpenAI Help: Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq); [OpenAI Help: What is memory](https://help.openai.com/en/articles/8983136-what-is-memory)
- The memory summary is a high-level view that doesn't list everything ChatGPT remembers. A "Sources" button shows which memories, chats or files influenced a reply. Temporary Chats neither use nor create memories (help-center extract) — [OpenAI Help: Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq)
- June 2026 release notes: memories are now updated automatically, and (June 12, 2026) a "Delete and turn off memory" option was added to the memory summary menu (help-center extract) — [ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)
- Free users got a "lightweight" memory improvement (short-term continuity across conversations), while chat-history reference was originally Plus/Pro [secondary, stale?] — [BGR](https://www.bgr.com/tech/everything-to-know-about-chatgpts-new-memory-upgrade-for-free-users/); [TechCrunch 2025-04-10](https://techcrunch.com/2025/04/10/openai-updates-chatgpt-to-reference-your-other-chats/) [stale?]
- Export: Settings → Data controls → Export data produces a ZIP of chat history (steps documented by Google for import into Gemini) — [Google Gemini Help: Import from other AI platforms](https://support.google.com/gemini/answer/16868299?hl=en&co=GENIE.Platform%3DDesktop). Third-party guides report the export contains conversations but **not saved memory entries**, and recommend copying the memory summary or prompting ChatGPT to list its memories [secondary] — [Notis](https://www.notis.ai/blog/can-you-export-your-chatgpt-memory/); [aichatexport.app](https://www.aichatexport.app/guides/chatgpt-data-export-what-is-included)
- One third-party claim of a March 2026 JSON memory export could not be confirmed from any OpenAI source [secondary, unverified] — [Medium](https://medium.com/@adi_leviim/can-you-take-your-ai-memory-with-you-52e882e94321)
- Import: no evidence of an official ChatGPT "import memory" feature; sources say ChatGPT builds memory only from conversations and there is no ingest setting [secondary] — [memx.app](https://memx.app/blog/can-you-move-your-ai-memory-between-apps/); [Bluehost](https://www.bluehost.com/blog/chatgpt-import-memory/)
- No memory API: none of the OpenAI developer docs read (MCP, Apps SDK auth/reference) mention any read or write access to ChatGPT memory — [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server); [OpenAI Apps SDK reference](https://developers.openai.com/apps-sdk/reference)

### Inferences
- mem's "paste-in import" for ChatGPT can only be a prompt like "Remember the following facts about me: …" pasted into a normal chat. Saved memories are created on request, so this plausibly works, but it is not a documented bulk-import path, and automatic memory management may consolidate or drop items.
- Exporting ChatGPT memory into mem means having the user paste the memory summary text, or the output of a "list everything you remember about me" prompt, into mem's `retain`. The data-export ZIP is useful for chat history only.

### Gaps
- Could not read the current Memory FAQ directly (403). The exact June 2026 UI (one unified control vs two toggles), per-item edit vs delete-only, and plan differences remain unverified. A third-party report of a 2026-06-04 single-control redesign was not attributable to a specific page.
- Whether the data export now includes memories: no official statement found.

## Gemini app (gemini.google.com and mobile): custom remote MCP; plus Gemini Enterprise as the org path

### Takeaway
Yes. Since 2026 the consumer Gemini app supports **custom apps** (remote MCP servers) added under Settings → Connected Apps on **web only**, and usable afterwards on mobile too. Limits: **US, 18+, personal Google account, English, Keep Activity on**. Auth is **DCR by default** or manual credentials under "Advanced". Writes always require manual confirmation, and `@app` ensures the server is used. Plan requirements are undocumented officially. Gemini Enterprise (Business edition) has an admin-added, Pre-GA custom MCP path: Streamable HTTP only, OAuth with client ID/secret or no auth, no DCR mentioned.

### Cited Findings
**Consumer Gemini app**
- Add: gemini.google.com → Settings → Connected Apps → "Custom apps" → "Add a custom app" → MCP server URL. Connecting is web-only; once connected, the app appears in both web and mobile apps. The server "must follow the standard MCP specification" — [Gemini Apps Help: Connect & manage custom apps](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DDesktop) [official, undated ©2026]; same article for [Android](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DAndroid) and [iOS](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DiOS)
- Eligibility: 18+, in the US, personal Google Account (work/school not supported "for now"), Keep Activity on, English only. No plan tier is named — [Gemini Apps Help: custom apps](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DDesktop)
- Plan tier is contested by third parties: one says only Google AI Pro/Ultra; another ties it to "Gemini Spark" for AI Pro (US English) and Ultra [secondary, unverified] — [usecarly](https://www.usecarly.com/blog/gemini-mcp/); [tactiq](https://tactiq.io/learn/google-gemini-mcp-support)
- Auth: Dynamic Client Registration is the default path. Servers without DCR need credentials entered under "Advanced features" (Show more). Connections are linked to the Google Account and can be unlinked or revoked from Google Account → Linked apps. No mention of CIMD, static headers or no-auth — [Gemini Apps Help: custom apps](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DDesktop)
- Writes: Gemini "requires manual confirmation for any write actions" — [Gemini Apps Help: custom apps](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DDesktop)
- Invocation: typing `@` and selecting the custom app ensures Gemini uses it. Custom apps also work in tasks/workflows and quick actions. Behaviour without `@` is not described — [Gemini Apps Help: custom apps](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DDesktop)
- Data: Gemini may share chat content and other sources (Connected Apps, Personal Intelligence, skills, tasks) with the app. Google does not control or secure third-party MCP servers. Developer tools: the "Connected Apps Platform" and Gemini Developer Mode at gemini.google.com/devmode (debugging, schema validation) — [Gemini Apps Help: custom apps](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DDesktop)
- Gemini desktop app: custom MCP configuration has only been seen in testing (2026-10-13) [secondary] — [Progressive Robot](https://www.progressiverobot.com/2026/10/13/gemini-desktop-app-mcp-support/)

**Gemini Enterprise (Business edition)**
- Pre-GA ("as is", limited support), page updated 2026-09-15. A team admin adds it under Manage team → Connected apps → Add MCP Server; new connections are disabled by default — [Gemini Enterprise Help: custom MCP server](https://support.google.com/g/answer/17106276?hl=en) [official]
- Transport: **StreamableHTTP only, legacy SSE not supported**. The server and IdP must be on public HTTPS — [Gemini Enterprise Help](https://support.google.com/g/answer/17106276?hl=en)
- Auth: No auth, or OAuth 2.0 with Authorization URL, Token URL, optional extra params, **Client ID + Client Secret**, and scopes (`offline_access` for refresh). Redirect `https://vertexaisearch.cloud.google.com/oauth-redirect`. No DCR or API-key option mentioned. On Cloud Run, Gemini adds `X-Serverless-Authorization` (Google-signed ID token) and passes the user token in `Authorization` — [Gemini Enterprise Help](https://support.google.com/g/answer/17106276?hl=en)
- Writes, confirmations, annotations: not covered on that page — [Gemini Enterprise Help](https://support.google.com/g/answer/17106276?hl=en)
- Workspace (work/school) accounts are excluded from consumer custom apps — [Gemini Apps Help: custom apps](https://support.google.com/gemini/answer/17209137?hl=en&co=GENIE.Platform%3DDesktop)

### Inferences
- For the owner's personal Google account in the US, mem can be added as a custom app if it implements OAuth with DCR, or a manual client in "Advanced". The static bearer key won't work.
- The Gemini connection originates from Google's cloud, so mem must be publicly reachable. Enterprise states this explicitly; for consumer it is implied because setup is a URL in a web UI.
- Every `retain`/`confirm_fact`/`dispute_fact` call will need a manual confirmation. Expect `@mem` to be needed for reliable use.
- Outside the US (or on a work account) the consumer path is unavailable, and the Gemini CLI/Antigravity CLI (covered in the CLI section below) is the fallback.

### Gaps
- Consumer Gemini: redirect/callback URI, transport (Streamable HTTP vs SSE), whether CIMD is supported, the exact fields under "Advanced", whether `instructions` and `readOnlyHint`/`destructiveHint` are honoured, and whether the server is consulted without `@`: all undocumented in the help page.
- Required Google AI plan for custom apps: not stated by Google; third-party claims conflict.
- Gemini Enterprise Standard/Plus editions: only the Business-edition page was found.

## Gemini built-in memory: what it stores, view/edit/delete, and import/export paths

### Takeaway
Gemini memory now lives under **Settings → Personal Intelligence**: a **Memory summary** (viewable, editable by prompt, with a change history), **Instructions for Gemini** (formerly "Saved info", editable list), and **memory of past chats**. There is an official **"Import memory to Gemini"** paste-prompt flow and a **chat-history ZIP import** (ChatGPT/Claude exports). Neither is available in the EEA, Switzerland or the UK. No official memory export or API was found. Takeout reportedly covers Gemini Apps activity (chats), but there is no confirmation that it includes memory.

### Cited Findings
- Memory summary: Settings → Personal Intelligence → Memory summary (or ask "What do you know about me?"). Edit or delete by prompting (e.g. "Remove my old phone number from your memory"); "Memory history" lists when details were added or changed; Memory can be toggled off there. Eligibility: personal account, 18+, Keep Activity on, Memory on, **US users with an active Google AI plan**, English, web and mobile — [Gemini Apps Help: Memory summary](https://support.google.com/gemini/answer/18617127?hl=en&co=GENIE.Platform%3DDesktop) [official, undated]
- Saved instructions: find, edit or delete under Settings → Personal Intelligence → Instructions for Gemini. The ability to remember specific info is "still rolling out" — [Gemini Apps Help: Manage what Gemini remembers](https://support.google.com/gemini/answer/16598625) [official, via search extract]
- Removing a detail learned from past chats requires deleting those chats from Gemini Apps Activity. For connected-app data, both disconnect and delete chats. Activity auto-deletes after 18 months by default (3/36/off configurable) — [Gemini Apps Help: Manage what Gemini remembers](https://support.google.com/gemini/answer/16598625); [Gemini Apps Help: Manage & delete activity](https://support.google.com/gemini/answer/13278892?hl=en&co=GENIE.Platform%3DAndroid); [Gemini Apps Help: memory of past chats](https://support.google.com/gemini/answer/16598469?hl=en&co=GENIE.Platform%3DAndroid)
- **Import memory:** Settings & help → "Import memory to Gemini" → copy Gemini's prompt → run it in the other AI → paste the response → "Add memory". Gemini creates a new chat thread and uses the content to remember details. The page doesn't say where the result shows up in settings — [Gemini Apps Help: Import from other AI platforms](https://support.google.com/gemini/answer/16868299?hl=en&co=GENIE.Platform%3DDesktop)
- **Import chats:** same screen → "Import chats" → upload a .zip (≤5 GB, ≤5 files/day; ChatGPT and Claude export steps given); processing up to a day. Re-uploading overwrites previously imported chats; imports can be deleted per chat or per ZIP — [Gemini Apps Help: Import](https://support.google.com/gemini/answer/16868299?hl=en&co=GENIE.Platform%3DDesktop)
- Import eligibility: personal account, 18+. **Not available in the EEA, Switzerland or the UK**, nor in Gemini in Messages, Chrome or Android XR. Imported data is used like Gemini Apps activity, including to improve services and train models — [Gemini Apps Help: Import](https://support.google.com/gemini/answer/16868299?hl=en&co=GENIE.Platform%3DDesktop); [Gemini Apps Privacy Hub](https://support.google.com/gemini/answer/13594961?hl=en)
- Launch: import tools announced late March 2026 [official blog; secondary news] [stale? ~7 months] — [Google blog: switch to Gemini](https://blog.google/innovation-and-ai/products/gemini-app/switch-to-gemini-app/); [gHacks 2026-03-31](https://www.ghacks.net/2026/03/31/google-adds-chatgpt-and-claude-import-tools-to-gemini-for-memory-and-chat-history/). A UK blog post says the import tools are for all consumer accounts, which conflicts with the help page's UK exclusion — [Google UK blog](https://blog.google/company-news/inside-google/around-the-globe/google-europe/united-kingdom/gemini-launches-new-personalisation-features-in-the-uk/)
- Export: third-party guides say Takeout → My Activity (filtered to Gemini Apps) exports gemini.google.com chats; a separate "Gemini" Takeout category holds Gems; there is no separate memory export [secondary, unverified] — [Univik](https://univik.com/help/export-gemini-chats.html); [Thredly](https://thredly.io/guides/gemini)

### Inferences
- mem's existing Gemini paste-in import matches the official "Import memory to Gemini" flow: paste text, then "Add memory". It is the only documented external write path into Gemini memory. There is no API.
- Getting Gemini memory into mem means copying the Memory summary text, or asking "What do you know about me?" and pasting the answer into `retain`.

### Gaps
- No official Google page found on whether Takeout includes Memory summary or Instructions for Gemini.
- Relationship between imported memory, Memory summary and Instructions for Gemini is undocumented.

## Microsoft Copilot: consumer copilot.microsoft.com vs Microsoft 365 Copilot / Copilot Studio

### Takeaway
**Consumer Copilot (personal Microsoft account): no documented custom MCP support.** It offers only fixed first-party connectors. **Microsoft 365 Copilot (work tenant + M365 Copilot licence)** supports custom MCP servers in three ways:
- **Custom federated connectors** (admin-created; Entra SSO, OAuth 2.0 with a pre-registered client, or no auth).
- **Declarative-agent MCP plugins** (Entra SSO, **DCR**, OAuth auth code, or anonymous; **no API key** for MCP).
- **Copilot Studio agents** (Streamable HTTP only; None, **API key header/query**, or OAuth 2.0 with DCR discovery, DCR or manual).

All of them call out from Microsoft's cloud.

### Cited Findings
**Consumer Copilot**
- Copilot connectors for personal accounts link only OneDrive, Outlook.com (mail/calendar/contacts), Google Drive, Gmail, Google Calendar and Google Contacts; rolled out to Windows Insiders 2025-10-09 [official] [stale?] — [Windows Insider Blog](https://blogs.windows.com/windows-insider/2025/10/09/copilot-on-windows-connectors-and-document-creation/)

Requires Global Administrator or AI Administrator, the Teams Developer Portal, developer name, website, privacy and terms URLs. ### Inferences

## Developer CLIs as fallback: OpenAI Codex CLI and Gemini CLI (now Antigravity CLI)

### Takeaway
Both CLIs connect **from the local machine** to remote Streamable HTTP MCP servers and accept **static headers/bearer tokens**, so mem's current API key works unchanged. Both also do OAuth: Codex supports CIMD, DCR or a pre-registered client; Gemini/Antigravity support DCR or a manual client. Caveat: **Gemini CLI stopped serving Google AI Pro/Ultra and free individual accounts on 2026-06-18**. Consumer users were moved to **Antigravity CLI**, which uses `serverUrl` + `headers` in `~/.gemini/config/mcp_config.json`.

### Cited Findings
**Codex CLI**
- `[mcp_servers.<name>]` in `~/.codex/config.toml`: `url`; `bearer_token_env_var`; `http_headers` (static); `env_http_headers`; `http_headers_helper` (local command emitting headers); `auth = "oauth"` default or `"chatgpt"`. If no credential resolves, it connects unauthenticated. Supports STDIO and Streamable HTTP; SSE not mentioned — [OpenAI Codex docs: MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) [official, undated]
- OAuth: `codex mcp login <server>` (`--scopes`); registration `auto` with CIMD or DCR (`--oauth-client-registration cimd|dcr`); pre-registered client via `--oauth-client-id`/`--oauth-client-secret`. Callback defaults to `http://127.0.0.1/callback` (+ server ID if no RFC 9207 `iss`), configurable via `mcp_oauth_callback_port` and `mcp_oauth_callback_url`. CIMD URLs `https://chatgpt.com/oauth/codex/client.json` or `.../codex/<callback_id>/client.json` — [OpenAI Codex docs: MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
- Approvals: `default_tools_approval_mode` = `auto` | `prompt` | `writes` (prompts for tools not marked read-only) | `approve`; per-tool overrides, `enabled_tools`/`disabled_tools` — [OpenAI Codex docs: MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

**Gemini CLI (enterprise/API-key users only since June 2026)**
- 2026-05-19 announcement: "On June 18, 2026, Gemini CLI will stop serving requests for Google AI Pro and Ultra" and free individual users (including Code Assist IDE extensions and Code Assist on GitHub). It remains usable with paid Gemini / Gemini Enterprise Agent Platform API keys and Code Assist Standard/Enterprise. Successor: Antigravity CLI — [GitHub discussion #27274](https://github.com/google-gemini/gemini-cli/discussions/27274) [official]; [The Register 2026-05-20](https://www.theregister.com/ai-ml/2026/05/20/bye-bye-gemini-cli-google-nudges-devs-toward-antigravity/5243605) [secondary]
- Config: `httpUrl` (Streamable HTTP) or `url` (SSE), `headers`. OAuth auto-discovery on 401 with DCR; optional `clientId`/`clientSecret`; redirect `http://localhost:<random-port>/oauth/callback`; `/mcp auth`; tokens in `~/.gemini/mcp-oauth-tokens.json`. `trust: true` skips confirmations; `includeTools`/`excludeTools` — [Gemini CLI docs: MCP servers](https://github.com/google-gemini/gemini-cli/blob/main/docs/tools/mcp-server.md) [official, undated]

**Antigravity CLI**
- Config `~/.gemini/config/mcp_config.json` (global) or `.agents/mcp_config.json` (workspace). Remote servers use `serverUrl` (or `url`) and `headers`; **Streamable HTTP only** (legacy SSE and `httpUrl` unsupported). OAuth: DCR automatic, or `oauth.clientId`/`clientSecret` with redirect `https://antigravity.google/oauth-callback`, authenticated via Agent settings → Customizations → Authenticate (paste the code back). Unconfigured MCP tools run in "Ask" mode (approve each call) — [Antigravity docs: MCP](https://antigravity.google/docs/mcp/) [official, undated]
- Bug report (Antigravity CLI v1.0.0): OAuth bearer token not sent on initialize, giving a 401. May be fixed [secondary, ~5 months old] — [GitHub issue #25](https://github.com/google-antigravity/antigravity-cli/issues/25)

### Inferences
- With today's static key, mem already works from Codex CLI (`bearer_token_env_var`) and Antigravity CLI (`headers`). These are the most reliable bridges for the owner while OAuth is being built.
- Gemini CLI's random-port loopback redirect and Codex's `127.0.0.1` callback mean mem's DCR must accept loopback redirect URIs with any port (RFC 8252 style).

### Gaps
- Whether Antigravity's MCP config is shared with the Antigravity desktop app's agent, and whether the OAuth bug is fixed: not confirmed.

## Cross-product summary for the planner: which apps can reach mem, on which plan, with what auth and write behaviour

### Takeaway
Today, with a static bearer key, mem is reachable only from **Codex CLI, Antigravity CLI/Gemini CLI, and Copilot Studio** (API-key header). Adding **OAuth 2.1 + PKCE with DCR** (and ideally CIMD and RFC 9207 `iss`) opens **ChatGPT web** (plan-gated for writes), the **consumer Gemini app** (US, personal account), **M365 Copilot MCP plugins** and **Copilot Studio Dynamic discovery**. **Consumer Microsoft Copilot cannot use custom MCP.** Every cloud app connects from vendor infrastructure, so mem needs a public HTTPS endpoint.

### Cited Findings
- ChatGPT: web only; OAuth (CIMD/DCR/static client) or no auth, no API keys; writes need confirmation; Pro read/fetch only and full write on Business/Enterprise/Edu (help-center extract) — [OpenAI Apps SDK: Authentication](https://developers.openai.com/apps-sdk/build/auth); [OpenAI: Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server); [OpenAI Help](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)

- Gemini Enterprise Business: admin, Pre-GA, Streamable HTTP, OAuth client ID/secret or none — [Gemini Enterprise Help](https://support.google.com/g/answer/17106276?hl=en)
- M365 Copilot federated connectors: admin, M365 Copilot licence, Entra SSO, OAuth client ID/secret or none — [Microsoft Learn: custom federated connectors](https://learn.microsoft.com/en-us/microsoft-365/copilot/connectors/set-up-custom-federated-connectors). MCP plugins: SSO, DCR, OAuth or anonymous; no API key — [Microsoft Learn: plugin authentication](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/plugin-authentication). Copilot Studio: Streamable HTTP; None, API key (header/query) or OAuth (DCR discovery, DCR, manual) — [Microsoft Learn: Copilot Studio MCP](https://learn.microsoft.com/en-us/microsoft-copilot-studio/mcp-add-existing-server-to-agent)

- Built-in memory write paths for external tools: none via API for ChatGPT, Gemini or Copilot. Gemini has an official paste-prompt "Import memory"; ChatGPT and Copilot only learn from conversation — [Gemini Apps Help: Import](https://support.google.com/gemini/answer/16868299?hl=en&co=GENIE.Platform%3DDesktop); [Microsoft Support: Copilot privacy controls](https://support.microsoft.com/en-us/privacy/microsoft-copilot/privacy-controls); [OpenAI Help: Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq)

### Inferences
- Minimum OAuth feature set for mem that covers the most clients: AS metadata + protected-resource metadata; PKCE S256; DCR that accepts fixed HTTPS redirects, per-connection redirects (Copilot Studio) and any-port loopback; RFC 9207 `iss`; audience-bound tokens; refresh tokens (`offline_access`). Add CIMD (`client_id_metadata_document_supported`), since ChatGPT prefers it and Codex supports it. Keep static-key auth for the CLIs and Copilot Studio.
- Mark read tools `readOnlyHint: true` and set explicit `destructiveHint`/`openWorldHint` on all tools. ChatGPT requires all three for submission, and Codex's `writes` mode keys off read-only marking.
- No surface documented here uses mem automatically in every chat. ChatGPT and Gemini need `@`-selection; Microsoft's orchestrators decide based on the server or connector description. So mem's server `instructions` and the description text matter.

### Gaps
- Gemini consumer and all Microsoft surfaces: handling of MCP `instructions` and tool annotations is undocumented.
- ChatGPT Plus write capability and post-July-2026 mobile/desktop availability are unverified.
