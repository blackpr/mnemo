# Long-term memory architectures for LLM agents: state of the art, benchmarks and production consensus (as of 23 Oct 2026)

Scope note: this file covers architectures, benchmarks and their disputes, key 2025-2026 papers, the long-context / provider-native question, and production design requirements. Dates are given per claim. Vendor-authored sources are flagged "(vendor)". Where sources conflict, both are listed.

## Key Question 1: Dominant architectural patterns and where each breaks down

### Takeaway
By late 2026 the field has converged on five recognizable families: (1) MemGPT/Letta-style self-edited, tiered in-context memory ("memory blocks" + archival tiers, optionally with a background "sleep-time" agent); (2) Mem0-style LLM-extracted atomic facts with ADD/UPDATE/DELETE reconciliation over a vector (+ optional graph) store; (3) Zep/Graphiti-style bi-temporal knowledge graphs with edge invalidation; (4) raw long context / filesystem-plus-grep "agentic retrieval"; and (5) newer "consolidating" systems (Hindsight, MemOS, EverMemOS, A-MEM, MemoryOS) that add reflection/observation layers. Surveys and same-harness evaluations agree that none dominates; each shifts cost between the write path and the read path and fails in a characteristic way (fact extraction brittleness, graph extraction latency, agent-tool-use variance, or context dilution).

### Cited Findings

**Taxonomies from 2026 surveys**
- The March 2026 survey "Memory for Autonomous LLM Agents" (arXiv 2603.07670, submitted 8 Mar 2026) formalizes agent memory as a write-manage-read loop and classifies systems along three dimensions: temporal scope (working/episodic/semantic/procedural), representational substrate (context-resident text, vector-indexed, structured SQL/KV/KG, executable repositories, hybrid), and control policy (heuristic, prompted self-control, learned control). It names five mechanism families: context-resident compression, retrieval-augmented stores, reflective self-improvement, hierarchical virtual context (MemGPT-style), and policy-learned management. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)
- The same survey describes three production patterns: Pattern A "monolithic context" (everything in prompt; prone to summarization drift), Pattern B "context plus retrieval store" (called the "workhorse" behind most production agents; main challenge is retrieval quality), Pattern C "tiered memory with learned control" (MemGPT, AgeMem; most headroom, most engineering/training cost). It recommends starting with B, instrumenting heavily, and moving to C only when data shows learned control helps. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)
- "From Storage to Experience" (arXiv 2605.06716, 7 May 2026, ACL 2026 Findings) proposes a three-stage evolutionary framing: Storage (trajectory preservation), Reflection (trajectory refinement), Experience (trajectory abstraction / cross-trajectory generalization), driven by long-range consistency, dynamic environments, and continual learning. — [arXiv 2605.06716](https://arxiv.org/abs/2605.06716)
- "A Survey of Agent Memory in the Second Half" (arXiv 2602.06052, early 2026) organizes the field by five memory types and five operations: storing, retrieval, updating, compression, forgetting. — [arXiv 2602.06052](https://arxiv.org/pdf/2602.06052) (as summarized by [The Nuanced Perspective, 16 May 2026](https://thenuancedperspective.substack.com/p/designing-agentic-memory-in-2026))
- "Agent Memory: Characterization and System Implications of Stateful Long-Horizon Workloads" (arXiv 2606.06448, v1 4 Jun 2026, v2 22 Sep 2026) is the first systems-level characterization: a four-axis taxonomy, a phase-aware profiler attributing cost to construction / retrieval / generation, ten systems characterized across two benchmark suites, and ten recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency trade-offs, and fleet-scale management. Its headline finding is that design choices shift cost between the write and read paths. — [arXiv 2606.06448](https://arxiv.org/abs/2606.06448)

**Pattern 1: MemGPT / Letta (self-edited tiered memory + sleep-time agent)**
- Letta "memory blocks" split the context window into labeled, size-capped, persisted units (e.g. "human", "persona", "knowledge"); the agent edits block values via memory tools; blocks are stored by `block_id` and the context window is recompiled from DB state on every request; multiple agents can share a block (used for sleep-time compute and multi-agent teams). Post dated 14 May 2025. — [Letta, Memory Blocks](https://www.letta.com/blog/memory-blocks/)
- Sleep-time compute splits an agent into a primary agent (cannot edit core memory) and a background sleep-time agent that holds the memory-editing tools and rewrites memory between turns. — [Letta, Sleep-time Compute](https://www.letta.com/blog/sleep-time-compute/); paper [arXiv 2504.13171](https://arxiv.org/pdf/2504.13171)
- Letta Code (2026) renames sleep-time to "dreaming" with a `/sleeptime` command; a 2026 comparison states `letta_v1_agent` replaced the MemGPT ReAct-style loop in October 2025. — [letta-code GitHub](https://github.com/letta-ai/letta-code); [Medium comparison, 2026](https://medium.com/@wasowski.jarek/i-compared-5-ai-agent-memory-systems-across-6-dimensions-none-wins-6a658335ed0a)
- Letta's own forum states that its lighter "AI Memory SDK" is in a prototype phase and that production systems needing sophisticated memory management should use the full Letta Platform. — [Letta forum](https://forum.letta.com/t/agent-memory-letta-vs-mem0-vs-zep-vs-cognee/88)
- Breakdown: a Letta launch HN thread raised irrelevant information accumulating in memory; co-founder Charles Packer replied that cross-project knowledge and learned preferences justify persistent context. — [via Letta forum summary](https://forum.letta.com/t/agent-memory-letta-vs-mem0-vs-zep-vs-cognee/88)
- In a Sep 2026 third-party local run (Letta 0.11.7), Letta had the best judge recall (52.2%) among Mem0/Zep/Letta but the slowest local search (318 ms p50) and "tighter runtime coupling". — [Effloow, 26 Sep 2026](https://effloow.com/articles/mem0-zep-letta-agent-memory-latency-benchmark-2026)

**Pattern 2: Mem0 (LLM-extracted facts, ADD/UPDATE/DELETE reconciliation)**
- Mem0 paper (arXiv 2504.19413, 28 Apr 2025): extracts, consolidates, retrieves salient facts; a graph variant models relationships and scores about 2% higher overall; claims 26% relative LLM-judge improvement over OpenAI memory on LoCoMo, 91% lower p95 latency and >90% token savings versus full-context. — [arXiv 2504.19413](https://arxiv.org/abs/2504.19413)
- Mem0's April 2026 algorithm (vendor): single-pass add-only extraction (agent-generated facts stored with same weight as user-stated); multi-signal retrieval fusing semantic similarity, BM25 and entity matching in parallel; entity linking replaced the external graph store and the `relations` field was removed, so relationships can no longer be traversed directly; scoping via `user_id`, `agent_id`, `run_id`/`session_id`, `app_id`/`org_id`. — [Mem0, State of AI Agent Memory 2026 (vendor, updated 10 Oct 2026)](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Breakdown (write cost): Mem0 2.1.0's extraction prompt is 33,653 characters (~8,478 tokens) and is re-sent on every ingested turn; across a 419-turn LoCoMo conversation input usage approached ~10M tokens before any question was asked; ingest cost 1.52 s/turn vs 38 ms p50 search. — [Effloow, 26 Sep 2026](https://effloow.com/articles/mem0-zep-letta-agent-memory-latency-benchmark-2026)
- Breakdown (fact rigidity): an HN commenter who tried Mem0 for an OpenClaw setup called extracted "facts" "far too rigid a tool for any actual job at hand", reporting a store of "largely incomplete, invalid, inefficient and unhelpful sentences", extraction breaking on irony/sarcasm and dates, and confusion when a booked trip changed; they reverted to prose summarization. The replying author of a competing store (YantrikDB) agreed the failure modes apply to any atomic-fact extractor and reported their own system merging "Alice is CEO" with "Sarah is CTO" on cosine similarity alone. — [HN comment, ~Apr 2026](https://news.ycombinator.com/item?id=47770220)
- Breakdown (no behavioural learning): an Ask HN (2026) characterizes Mem0 as "memory storage + retrieval. Doesn't learn patterns" and Letta as "self-editing agent memory. Closer, but no implicit learning from behavior"; the poster argues user corrections are the highest-signal data. — [Ask HN](https://news.ycombinator.com/item?id=46891715)

**Pattern 3: Zep / Graphiti (bi-temporal temporal knowledge graph)**
- Graphiti ingests "episodes" (raw messages/text/JSON, kept as non-lossy provenance), automatically extracts entities (nodes) and edges (facts), groups into communities, supports custom entity types; edges carry temporal metadata for point-in-time queries; contradictions are handled by temporal edge invalidation rather than deletion; retrieval is hybrid (vector + BM25 + graph traversal) with no LLM reranking in the loop, plus distance-from-node reranking; backends Neo4j, FalkorDB, Amazon Neptune; LLM providers OpenAI, Azure OpenAI, Gemini, Anthropic. — [Graphiti overview docs](https://help.getzep.com/graphiti/getting-started/overview)
- Bi-temporal fields: `valid_at`/`invalid_at` (world time) and `created_at`/`expired_at` (transaction time); the model is defined in the Zep paper arXiv 2501.13956 (Jan 2025) and has been reused by downstream projects. — [Zep temporal KG page (vendor)](https://www.getzep.com/ai-agents/temporal-knowledge-graph/); [third-party PR citing the Zep model](https://github.com/topcheer/ggcode/pull/2531)
- Product status: Graphiti is the open-source engine; Zep is the managed product built on it; the old self-hosted Zep server is deprecated. — [Signals/aktagon, Jul 2026](https://signals.aktagon.com/articles/2026/07/zep-a-temporal-knowledge-graph-architecture-for-agent-memory/)
- Breakdown (write cost): Zep/Graphiti 0.30.2 local ingest 3.65 s/turn (slowest of three), 163 ms p50 search, smallest retrieved context (212 tokens), 37.0% judge recall in the Effloow reference run. — [Effloow, 26 Sep 2026](https://effloow.com/articles/mem0-zep-letta-agent-memory-latency-benchmark-2026)
- Letta's view: knowledge graphs "may help in specific domains but can be harder for the LLM to understand"; simpler tools are more likely to be used well. — [Letta, Aug 2025](https://www.letta.com/blog/benchmarking-ai-agent-memory)

**Pattern 4: Long context / filesystem + agentic search**
- Letta (12 Aug 2025): a GPT-4o-mini Letta agent given only file tools (`grep`, `search_files`, `open`, `close`, plus `answer_question`) over the raw conversation file scored 74.0% on LoCoMo vs Mem0's self-reported 68.5% graph variant; Letta attributes this to models being heavily trained on filesystem operations and to iterative query rewriting. — [Letta, Benchmarking AI Agent Memory](https://www.letta.com/blog/benchmarking-ai-agent-memory)
- LongMemEval-V2 (12 May 2026): a coding-agent-over-files approach (AgentRunbook-C) scored 72.5% vs 48.5% for the strongest RAG baseline and 69.3% for an off-the-shelf coding agent, but with high latency. — [arXiv 2605.12493](https://arxiv.org/abs/2605.12493)
- Anthropic's memory tool (29 Sep 2025, public beta) is explicitly file-based: Claude can "create, read, update, and delete files in a dedicated memory directory"; it "operates entirely client-side through tool calls" with developer-managed storage. — [Anthropic/Claude blog](https://claude.com/blog/context-management)

**Pattern 5: Consolidating / "memory OS" systems**
- A-MEM (NeurIPS 2025): Zettelkasten-style notes with contextual descriptions, keywords, tags, links to related memories; new memories can trigger updates of older notes' attributes; GPT-4o-mini multi-hop F1 45.85 vs 18.41 for LoCoMo baseline; ~2,520 avg tokens vs 16,910 for full context. — [arXiv 2502.12110](https://arxiv.org/pdf/2502.12110); [NeurIPS page](https://papers.nips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html)
- MemoryOS (arXiv 2506.06326, 2025): hierarchical short/mid/long-term persona memory with heat-based eviction; criticizes A-MEM's multi-step link generation for inflating latency and error accumulation. — [arXiv 2506.06326](https://arxiv.org/pdf/2506.06326)
- MemOS (MemTensor, arXiv 2507.03724) and EverMemOS (arXiv 2601.02163, Jan 2026) are "memory operating system" designs; MemOS is the only system whose vendor README numbers match the same-harness OmniMemEval run (which MemTensor itself operates). — [arXiv 2507.03724](https://arxiv.org/pdf/2507.03724); [arXiv 2601.02163](https://arxiv.org/pdf/2601.02163); [aiagentmemory.org leaderboard](https://aiagentmemory.org/articles/agent-memory-leaderboard/)
- Hindsight (Vectorize, paper arXiv 2512.12818, Dec 2025): "retain, recall, reflect" with an observations layer for knowledge consolidation, a fact-extraction filter at write time, LLM-powered merge consolidation, recency boost at retrieval, and no native eviction by design (compliance deletion at the "bank" level). Hindsight 1.0 and the "Memlake" object-storage engine shipped the week of 15 Oct 2026; the project reports >30,000 Hindsight Cloud users, ~53k GitHub stars, stays open source and Postgres-based; Memlake claims 100M memories at <100 ms p99 on object storage (vendor, unverified). — [arXiv 2512.12818](https://arxiv.org/pdf/2512.12818); [Hindsight consolidation post, 21 May 2026](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation); [Hindsight 1.0 / 50k stars, 15 Oct 2026](https://hindsight.vectorize.io/blog/2026/10/15/hindsight-50k-stars)
- Cognee: three-store graph+vector+relational design (defaults per Cognee: Kuzu graph, LanceDB vector, SQLite relational; a third-party guide says PostgreSQL+pgvector, so check current docs); v1.0 API centers on remember/recall/improve/forget; Cognee's Jan 2026 HotpotQA benchmark ran Cognee tuned (GRAPH_COMPLETION_COT) vs Graphiti/LightRAG/Mem0 on defaults (0.85 vs 0.54 DeepEval correctness vs Mem0), so configurations were not matched. — [Cognee, how it builds memory (vendor)](https://www.cognee.ai/how-cognee-builds-ai-memory); [Cognee vs Mem0 (vendor)](https://www.cognee.ai/cognee-vs-mem0); [Vectorize comparison (vendor)](https://vectorize.io/articles/mem0-vs-cognee)
- LangMem (LangChain): repo still active (commits to 7 Jun 2026) but latest PyPI release 0.0.30 dates from 27 Oct 2025; it was not retired when LangChain 1.0 deprecated legacy memory classes. Hindsight's May 2026 comparison characterizes LangChain memory primitives as window/summary "compaction rather than consolidation" with no merge or decay. A third-party comparison reports LangMem p95 search of 59.82 s vs Mem0 0.200 s (unverified). — [rywalker LangMem review, Jun 2026](https://rywalker.com/research/langmem); [Hindsight consolidation post](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation); [FutureAGI roundup](https://futureagi.com/blog/best-llm-agent-memory-tools-2026/)

**How the named systems handle consolidation levers (Hindsight's table, 21 May 2026, vendor)**
- Mem0: importance LLM-driven at write; merge LLM-driven ADD/UPDATE/DELETE; no native decay; explicit DELETE eviction. Zep/Graphiti: fact-extraction importance; entity-aware merge; strongest decay via temporal validity intervals; explicit invalidation. Letta: agent decides importance and merge; no native decay; eviction via core-to-archival tier transitions. LangChain: window/summary; no merge or decay; window-based eviction. Hindsight: fact-extraction filter; LLM consolidation merge; recency boost; no native eviction. — [Hindsight consolidation post](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)

### Inferences
- The architectural split that matters most for a provider-agnostic layer is write-time extraction (Mem0, Zep, Hindsight, Cognee: expensive, model-dependent, brittle to irony/dates/state changes) versus read-time agentic search over raw or lightly structured history (Letta filesystem, AgentRunbook-C, Anthropic memory tool: cheap writes, cost and variance pushed to the answering model's tool use). Hybrids that keep raw episodes as provenance and layer extracted facts on top (Graphiti episodes, Hindsight) are the common middle ground.
- Because every extraction-based system's quality is bounded by the extraction model, a provider-agnostic layer should treat the extraction/consolidation model as a pluggable, versioned dependency and log which model wrote each fact (the "tenure crossover" and HaluMem results below make this a correctness issue, not just an ops nicety).

### Gaps
- No independent, controlled comparison of Letta's sleep-time/dreaming against synchronous write-time extraction was found; the "18% accuracy and 2.5x cost reduction" claim circulating in 2026 blogs could not be traced to the primary paper.
- Mem0's removal of the `relations` field and shift to entity-linking is only documented in a vendor post; no changelog or migration note was located.
- The full MemoryOS vs A-MEM LoCoMo table was not read; exact numbers are not recorded here.

## Key Question 2: What the benchmarks show, who leads, and known criticisms

### Takeaway
On vendor-reported numbers, LoCoMo and LongMemEval are effectively saturated: Mem0 (92.5 / 94.4), Zep (94.7 / 90.2), Hindsight (92.0 / 94.6), Honcho (89.9 / 90.4), MemOS (88.8 / 89.2) all sit within a few points, which is inside the measured noise (about +/-3.1 points 95% CI on LoCoMo; a 26-point swing from changing only the grading prompt). The only same-harness run (OmniMemEval, operated by MemOS's maker) reorders everything and drops most vendors by 15-40 points. The practitioner consensus in 2026 is that these two benchmarks now mostly measure "whether your LLM can read", have 6-7% flawed answer keys, do not test writes/updates/forgetting, and should be replaced or supplemented by BEAM (1M-10M tokens), LongMemEval-V2, MemoryArena, HaluMem, and task-specific evals with a full-context baseline.

### Cited Findings

**Benchmark definitions and sizes**
- LoCoMo (Maharana et al., 2024): ~9,000 tokens (Mem0's figure) or 16k-26k tokens (Hindsight's figure) per conversation, ~300 turns, up to 35 sessions, 1,540 questions in the common split (Mem0) / 1,536 (Dakera); QA categories single-hop, multi-hop, temporal, open-domain, adversarial; original paper reports F1, vendors report LLM-judged accuracy. — [Mem0 benchmarks guide (vendor)](https://mem0.ai/blog/ai-memory-benchmarks-in-2026); [hindsight-benchmarks repo](https://github.com/vectorize-io/hindsight-benchmarks); [Dakera](https://dakera.ai/benchmark/)
- LongMemEval (Wu et al., arXiv 2410.10813, 2024): 500 questions across information extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention (`_abs` questions about events that never happened); LongMemEval_S ~115k tokens / ~40 sessions, LongMemEval_M ~500 sessions; official judge script uses GPT-4o; the paper found a 30% accuracy drop for commercial assistants and long-context LLMs on sustained-interaction memory. — [Mem0 benchmarks guide](https://mem0.ai/blog/ai-memory-benchmarks-in-2026)
- BEAM ("Beyond a Million Tokens", ICLR 2026): 100 conversations up to 10M tokens, 2,000 probing questions, ten capabilities (fact/entity tracking, updates, contradiction resolution, temporal ordering, instruction-vs-preference, multi-hop, ...); tracks BEAM-1M and BEAM-10M; its LIGHT framework beat the strongest long-context baselines by 3.5-12.7%, widening at scale. — [Mem0 benchmarks guide](https://mem0.ai/blog/ai-memory-benchmarks-in-2026)
- LongMemEval-V2 (arXiv 2605.12493, 12 May 2026, work in progress): 451 curated questions over web-agent trajectories of up to 500 trajectories / 115M tokens; five abilities: static state recall, dynamic state tracking, workflow knowledge, environment gotchas, premise awareness; "context gathering" formulation (memory returns compact evidence to a downstream QA model). — [arXiv 2605.12493](https://arxiv.org/abs/2605.12493)
- MemBench (2025) separates factual vs reflective memory and participation vs observation modes, and measures effectiveness, efficiency (number of memory operations) and capacity; MemoryAgentBench (2025) tests accurate retrieval, test-time learning, long-range understanding and selective forgetting (no system masters all four; most fail selective forgetting); MemoryArena (2026) uses interdependent multi-session agentic tasks in four domains where near-perfect LoCoMo systems fall to 40-60%. — [arXiv 2603.07670 survey](https://arxiv.org/html/2603.07670v1)
- HaluMem (arXiv 2511.03506, Nov 2025): operation-level evaluation of memory extraction, updating and QA; HaluMem-Medium and HaluMem-Long each ~15k memory points and >3.4k queries, Long variant in the millions of tokens; finds systems generate and accumulate errors during extraction and updating that propagate to QA, with high omission rates. — [arXiv 2511.03506](https://arxiv.org/pdf/2511.03506)
- Letta Context-Bench (2026): tests "agentic context engineering" (what to retrieve/load/manage) with a Filesystem Suite (graded on correctness and path efficiency) and a Skills Suite; model scores as of 13 Mar 2026: GPT-5.2-Codex (xhigh) 93%, GPT-5.4 (xhigh) 89%; many open-source models below 50%. — [AgentMarketCap, 5 Apr 2026](https://agentmarketcap.ai/blog/2026/04/05/context-bench-letta-benchmark-agent-memory-long-running-sessions); primary leaderboard at leaderboard.letta.com
- Hindsight's "Agent Memory Benchmark" (AMB, 23 Mar 2026) adds LifeBench and PersonaMem and calls for measuring accuracy, speed, cost and usability together, agentic datasets (memory across tool calls), published judge/answer prompts, and single-query vs agentic modes on the same data. — [Hindsight manifesto](https://hindsight.vectorize.io/blog/2026/03/23/agent-memory-benchmark)

Mem0's CTO then flagged that Zep had excluded Category 5 (adversarial) from the denominator while keeping its correct answers in the numerator; Zep corrected to 75.14% (+/-0.17). Zep's own paper (arXiv 2501.13956) reports no LoCoMo numbers. — [braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html); [Atlan Zep vs Mem0](https://atlan.com/know/zep-vs-mem0/)
- In 2026 both vendors claim 92-95 on LoCoMo (Mem0 92.5 with gpt-5 answering and grading plus a new, more lenient grading prompt; Zep 94.7 with gpt-5.4 reasoning as answerer and grader); Dakera: "Mem0 contests Zep's methodology, and Zep disputes Mem0's"; the figures are not comparable. — [Dakera](https://dakera.ai/benchmark/); [braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)
- Letta's 74.0% (Aug 2025) compared against Mem0's 68.5% is itself criticized as a vendor benchmarking its own framework against a competitor's self-reported number. — [Signals/aktagon, Feb 2026](https://signals.aktagon.com/articles/2026/02/benchmarking-ai-agent-memory-is-a-filesystem-all-you-need/)

**Documented flaws in LoCoMo / LongMemEval**
- Hindsight repo lists five LoCoMo problems: missing or flawed ground truth (categories lacking answers, speaker attribution errors, inconsistent correctness marking), ambiguous questions, insufficient challenge (16k-26k tokens fits in context), no tests for knowledge updates or temporal reasoning, data quality (image references without descriptions, unrealistic dialogue); the adversarial category is "nearly impossible to evaluate reliably" and is skipped. — [hindsight-benchmarks repo](https://github.com/vectorize-io/hindsight-benchmarks)
- Answer-key audits: CoreDotToday (Claude Sonnet 5.5 + human spot checks) found 52 wrong and 56 ambiguous references in 1,540 LoCoMo questions (7.0% combined, 3.4% wrong; open-domain 30.2%); Penfield's separate audit found 99 score-corrupting errors (6.4%). — [braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)
- Grading sensitivity: re-grading the same 1,540 gpt-4o-mini answers with a different grading prompt (same grader gemini-3.1-flash-lite) moved the score from 55.8% to 81.4%; changing only the grader model with Mem0's 2025 prompt gave 74.0 (gpt-4o-mini) / 70.3 (Gemini) / 62.1 (Haiku); the Mem0 2026 grading rule accepts hedged multi-candidate answers and dates within 14 days. — [braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)
- Statistical noise: because LoCoMo questions cluster in ten conversations, the 95% CI is about +/-3.1 points (not +/-2.3 under independence) and the minimum detectable difference between two systems is about 4.5 points; Mem0's guide assumed independence and reported +/-1.3 at 92.5. — [braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)
- Vectorize (23 Mar 2026): both benchmarks were designed for 32k context; on most instances a naive everything-in-context approach now scores competitively, so "the benchmarks that were designed to stress retrieval now mostly measure whether your LLM can read"; small changes in judge/answer prompts "can swing accuracy scores by double digits"; both remain useful for regression testing. — [Hindsight manifesto](https://hindsight.vectorize.io/blog/2026/03/23/agent-memory-benchmark)
- Mem0's own guide concedes public benchmarks "mostly grade retrieval", rarely test writes/forgetting/consolidation, none test per-user isolation under concurrent load, and token cost/latency are usually missing. — [Mem0 benchmarks guide (vendor)](https://mem0.ai/blog/ai-memory-benchmarks-in-2026)
- Scores measure answers, not stored memory: one paper found QA scores and memory-store quality diverge by an average of 16 points. — [aiagentmemory.org leaderboard](https://aiagentmemory.org/articles/agent-memory-leaderboard/)
- "Ground Truth First" (arXiv 2607.21962, 24 Jul 2026) argues existing benchmarks generate conversations first and extract answer keys afterward (causing label errors and contamination) and test only short histories; it builds facts with validity intervals, volatility classes and source channels first, then renders chat/email and verifies every planted fact (~380 questions, 15 types). — [arXiv 2607.21962](https://arxiv.org/abs/2607.21962)

**Horizon effects and write-quality effects**
- "Tenure crossover": a budgeted curated-map memory leads at three weeks but falls from 96% to 72% recall of evicted content by nine weeks, while a provenance-typed graph rises to 90% at nine weeks (holds for all six users, exact p=0.031); a full-rendered-history baseline ties or beats the best memory system at three weeks but has no judge-independent advantage at nine weeks at ~2x read cost; the layered Veracium architecture scored 96.8% at the short horizon; weakly written facts fail 24% of the time vs 2% for others. — [arXiv 2607.21962](https://arxiv.org/abs/2607.21962)
- Scale degradation: Mem0 falls from 64.1 (BEAM-1M) to 48.6 (BEAM-10M), ~25%, as context grows 10x; Mem0 names temporal reasoning as "still the hardest category" and open-domain (72.7) its weakest LoCoMo category. — [Mem0 State of Memory 2026 (vendor)](https://mem0.ai/blog/state-of-ai-agent-memory-2026); [Mem0 benchmarks guide](https://mem0.ai/blog/ai-memory-benchmarks-in-2026)

### Inferences
- Any ranking derived from vendor-reported LoCoMo/LongMemEval numbers in 2026 is not decision-grade: the spread between leading systems (about 2-5 points) is inside the measured noise floor and inside the swing caused by grader choice alone. The same-harness OmniMemEval table is the only apples-to-apples public data, but it is operated by a vendor that tops it.
- For an engineering team, the defensible evaluation is the one CoreDotToday and Vectorize both converge on: run your own harness on your own data, always include a full-context baseline with the same answering model, publish grader prompt and dropped questions, and report cost and latency alongside accuracy. If a memory system cannot beat full-context on accuracy, its justification is cost/latency, not quality.
- BEAM-10M, MemoryArena, HaluMem and the nine-week horizon results are the benchmarks that currently discriminate between architectures; LoCoMo/LME-S are regression tests.

### Gaps
- No official leaderboard exists for LoCoMo or LongMemEval; all leaderboards are vendor-run or vendor-collected. No independent audit of the 2026 92-95% claims was found.
- The original Zep "Lies, Damn Lies & Statistics" post (May 2025) was not fetched directly; its content is reported via secondary synthesis.
- Full OmniMemEval methodology/repository was not located; results are quoted from a snapshot on a secondary aggregator.
- Per-system BEAM results from the BEAM paper itself (which systems, which scores) were not read.

## Key Question 3: Key papers from 2025-2026 (surveys, consolidation/forgetting, coding agents, multi-agent, security)

### Takeaway
2026 produced a dense literature: several broad surveys (ACL 2026 Findings "From Storage to Experience"; "Memory for Autonomous LLM Agents"; "Agent Memory in the Second Half"; "Always-On Agents"; a dedicated memory-security survey), a systems-characterization paper, a cluster of forgetting/decay/reconsolidation papers, a new sub-field of memory for coding agents (MemTrace, REM, PROJECTMEM, MOOSEDev, VibeMemBench), and a governance-centric multi-agent memory literature (MemClaw, Mesh Memory Protocol, MemCollab). The common thread is a shift from "retrieval" to "what to store, when to update, what to forget, and who may see it".

## Key Question 4: Long context windows and provider-native memory vs an external layer; cost/quality trade-offs

### Takeaway
Very long context (1M+) has eroded the quality argument for external memory on short histories: full-context baselines now match or beat most memory systems on LoCoMo-scale data, and a nine-week longitudinal study found full history ties the best memory system at three weeks. But the evidence that external memory still matters comes from scale (BEAM-10M, MemoryArena, 115M-token LME-V2 trajectories), cost (full context costs roughly an order of magnitude more per turn; context editing alone cut tokens 84% in Anthropic's eval), cross-session/cross-provider persistence, deletion/access control, and the observation that bigger windows can actively hurt. Provider-native memory (ChatGPT memory, Claude memory, Gemini/Vertex Memory Bank, Anthropic's API memory tool) sets a UX bar but is platform-locked, so a provider-agnostic team cannot rely on it.

### Cited Findings

**Where long context wins or ties**
- Vectorize (Mar 2026): on most LoCoMo/LongMemEval instances "a naive approach that places everything in context scores competitively", so a cheap, well-architected memory system may score the same as a brute-force context-stuffer. — [Hindsight manifesto](https://hindsight.vectorize.io/blog/2026/03/23/agent-memory-benchmark)
- CoreDotToday (Oct 2026): no-memory full-context gemini-3.1-flash-lite scored 80.7% on LoCoMo (vs 2025 published Zep 75.14, Mem0 66.88, different answering models); recommendation: "Measure a full-context baseline with the same answering model. If a memory system cannot beat it, its value lies in cost and latency." — [braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)
- Ground Truth First (Jul 2026): full-rendered-history baseline ties or beats the best memory system at three weeks, with no judge-independent advantage at nine weeks and ~2x the read cost. — [arXiv 2607.21962](https://arxiv.org/abs/2607.21962)
- Redis-cited LoCoMo study: full-context 72.9% accuracy at 17.12 s p95 vs selective external memory 66.9% at 1.44 s. — [Redis blog](https://redis.io/blog/long-term-memory-architectures-ai-agents/)
- Older hindsight-benchmarks data: full-context GPT-4o scored only 60.2 on LongMemEval-S vs 71.2 for Zep and 91.4 for Hindsight (Gemini-3), showing how model generation changes the comparison. — [hindsight-benchmarks repo](https://github.com/vectorize-io/hindsight-benchmarks)

**Where external memory still wins**
- Mem0 (vendor): BEAM "cannot be solved by simply expanding the context window"; attention degrades across long spans. — [Mem0 State of Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- BEAM paper (ICLR 2026): memory-augmented LIGHT beats the strongest long-context baselines by 3.5-12.7%, gap widening at scale. — [via Mem0 benchmarks guide](https://mem0.ai/blog/ai-memory-benchmarks-in-2026)
- Survey (Mar 2026): MemoryArena task completion dropped from >80% to ~45% when an active memory agent was replaced by a long-context-only baseline; long context has attention dilution, quadratic cost growth, no persistent cross-session storage, and no deletion or access control; RAG beats pure long-context "across the board" (qualitative). — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)
- Practitioner (May 2026): in the MIA paper, enlarging the context window made performance worse; compressing history into actionable workflow summaries consistently beat raw retention; a 7B model with MIA's three-role design beat a 32B baseline by 18%. — [The Nuanced Perspective](https://thenuancedperspective.substack.com/p/designing-agentic-memory-in-2026)
- Databricks (Apr 2026, via secondary): accuracy rose from 2.5% to >50% after 62 log records, surpassing an expert-curated baseline; reasoning steps dropped from ~19 to 4.3; LLM-filtered raw logs beat hand-engineered instructions; but without forgetting, agents reused earlier incorrect results with more confidence because memory made wrong answers look like precedent. — [The Nuanced Perspective](https://thenuancedperspective.substack.com/p/designing-agentic-memory-in-2026)
- Lost-in-the-middle persists even in long-context-tuned models. — [Atlan](https://atlan.com/know/in-context-vs-external-memory-ai-agents/)

**Cost and latency numbers**
- Mem0 paper: 91% lower p95 latency and >90% token savings vs full context (2025). — [arXiv 2504.19413](https://arxiv.org/abs/2504.19413)
- Mem0 2026: ~6.7-7.0K tokens per retrieval vs ~26,000 tokens per conversation for full context in the 2025 paper (different units); p50 <=1.1 s on all four benchmarks; Zep claims 189 ms retrieval. — [Mem0 State of Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026); [Mem0 benchmarks guide](https://mem0.ai/blog/ai-memory-benchmarks-in-2026)
- Hindsight: full-history prompts cost "roughly an order of magnitude more per turn" than a curated subset at 128K windows and frontier pricing (estimate). — [Hindsight consolidation post](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)
- Hindsight's default returns about 4x more tokens per retrieval than Mem0 (token budget differences affect scores). — [aiagentmemory.org](https://aiagentmemory.org/articles/agent-memory-leaderboard/)
- Effloow (Sep 2026): local search p50 Mem0 38 ms / Zep 163 ms / Letta 318 ms; ingest Mem0 1.52 s / Zep 3.65 s / Letta 0.37 s per turn; storage for 10,000 users x 200 memories (2M records): ~2 GB text+metadata, ~12.3 GB of 1,536-dim float32 vectors, ~15-25 GB primary, 45-75 GB with three copies; at 100 requests/user/month each extra 300 retrieved tokens adds ~300M input tokens/month; recommends pgvector as default and specialized memory only when it beats that baseline on your workload. — [Effloow](https://effloow.com/articles/mem0-zep-letta-agent-memory-latency-benchmark-2026)
- Survey: retrieval adds 200-500 ms; mitigations async writes and parallel retrieval. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)
- Anthropic (29 Sep 2025): context editing alone cut token consumption by 84% in a 100-turn web-search eval and improved an agentic-search eval by 29%; memory tool + context editing improved it by 39% over baseline (internal evals, Sonnet 4.5). — [Claude blog](https://claude.com/blog/context-management)

**Provider-native memory (as of Oct 2026)**
- Anthropic API: memory tool (file-based, client-side, developer-managed storage) and context editing (`clear_tool_uses_20250919` strategy clears oldest tool results; beta header `context-management-2025-06-27`), public beta on Claude Developer Platform, Bedrock and Vertex AI. — [Claude blog](https://claude.com/blog/context-management); [Helicone docs](https://docs.helicone.ai/gateway/concepts/context-editing.md)
- Google: Vertex AI Agent Engine Memory Bank (public preview 8 Jul 2025) extracts facts asynchronously with Gemini from Agent Engine sessions, consolidates and resolves contradictions over time, exposes a REST API and ADK/LangGraph/CrewAI integrations; a Redis re-measurement put it at 42.4% on LoCoMo vs ~70% in the original paper (secondary). — [Virtualization Review, 9 Jul 2025](https://virtualizationreview.com/articles/2025/07/09/googles-vertex-ai-memory-bank-and-the-industry-shift-to-persistent-context.aspx); [Google Cloud blog](https://cloud.google.com/blog/ja/products/ai-machine-learning/vertex-ai-memory-bank-in-public-preview); [braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)
- Consumer products: ChatGPT has saved memories plus implicit recall with a background consolidation process; Claude memory reached free users 2 Mar 2026 and (per third-party descriptions) uses a periodic synthesis plus search over raw past chats with citations, with memory stored as human-readable markdown the user can edit; Gemini memory is tied to the Google account (personal accounts only) and offers import from ChatGPT/Claude. All are platform-locked. Sources are third-party blogs and conflict on details (real-time vs batched updates, context sizes). — [memoryplugin blog](https://blog.memoryplugin.com/claude-vs-chatgpt-vs-gemini-memory/); [Notebookcheck](https://www.notebookcheck.net/AI-that-remembers-ChatGPT-Gemini-and-Claude-compared.1336513.0.html)
- OpenAI memory as a baseline in memory papers: 52.90 on LoCoMo in the Hindsight/Mem0-era tables (2025). — [hindsight-benchmarks repo](https://github.com/vectorize-io/hindsight-benchmarks)

### Inferences
- The honest 2026 case for an external, provider-agnostic memory layer is not "higher accuracy than full context" (that is no longer reliably true at LoCoMo scale); it is (a) cost and latency at 10-100x lower tokens per turn, (b) histories beyond what any window holds (BEAM-10M, multi-month tenures), (c) portability across Claude/Gemini/OpenAI, and (d) governance: deletion, access control, provenance and poisoning defenses that no context window provides.
- Anthropic's file-based memory tool and Letta's filesystem results suggest a provider-agnostic layer should expose memory as a filesystem-like or tool interface that frontier models already use well, with structured extraction as an optional layer underneath rather than the only access path.

### Gaps
- No public, controlled study comparing 1M+ context (Gemini-class) directly against the leading 2026 memory systems on the same data was found; the full-context numbers available use different, often smaller models.
- OpenAI's developer-facing (Responses API) memory/state features in 2026 were not located in search results; status unknown here.
- Vertex Memory Bank benchmark numbers come from a secondary citation of a Redis re-measurement; the primary was not fetched.

## Key Question 5: Design elements considered mandatory for production

### Takeaway
Across surveys, vendor engineering posts, and the production-oriented papers, the recurring mandatory list is: explicit write policy (filter/canonicalize/dedupe/score before storing; store facts or validated summaries, not raw turns); entity resolution and conflict handling at write time with explicit invalidation rather than silent overwrite; bi-temporal validity (valid-time and transaction-time) so point-in-time queries and supersession work; provenance on every memory (source episode, writer identity, model version, confirmation state); scoping/tenancy (user/agent/session/org) enforced on every read path including direct GETs; decay only where state changes are tracked, eviction only for compliance; operation-level evals (extraction, update, QA) with a full-context baseline, published grader, and cost/latency; and observability (memory diffs, replay, invalidation events). Poisoning defenses are now a standard requirement, not an extra.

### Cited Findings

**Write policy, dedup, importance**
- Survey write-path practices: filtering, canonicalization, deduplication, priority scoring, metadata tagging; read path: two-stage retrieval, retrieval gating, token budgeting, caching. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)
- Hindsight: importance via LLM 1-10 scoring (Park et al. 2023) adds a model call per write and drifts across model versions; fact extraction as a write-time filter is the alternative; recommended default "store facts, not turns". — [Hindsight consolidation post](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)
- Write quality predicts downstream quality: weakly written facts fail 24% vs 2% for others. — [arXiv 2607.21962](https://arxiv.org/abs/2607.21962)
- HaluMem: errors introduced at extraction and update propagate to QA; calls for "interpretable and constrained memory operation mechanisms". — [arXiv 2511.03506](https://arxiv.org/pdf/2511.03506)
- Mem0 2026 stores agent-generated facts with the same weight as user-stated facts (vendor); Databricks found un-forgotten wrong results became "precedent". — [Mem0 State of Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026); [The Nuanced Perspective](https://thenuancedperspective.substack.com/p/designing-agentic-memory-in-2026)
- Pipeline ordering matters: a synchronous near-duplicate gate can reject contradictory writes before an asynchronous contradiction detector evaluates them (MemClaw production finding). — [arXiv 2606.24535](https://arxiv.org/abs/2606.24535)

**Conflict resolution and temporal validity**
- Conflict policies: recency-wins, source-wins, confidence-wins; recommend recency-wins with explicit invalidation; poorly calibrated confidence-wins causes "runaway certainty". — [Hindsight consolidation post](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)
- Bi-temporal model (`valid_at`/`invalid_at`, `created_at`/`expired_at`); superseded facts are invalidated, not deleted, enabling point-in-time queries. — [Zep temporal KG](https://www.getzep.com/ai-agents/temporal-knowledge-graph/); [Graphiti docs](https://help.getzep.com/graphiti/getting-started/overview)
- Survey staleness practices: temporal versioning, source attribution, contradiction detection, periodic consolidation. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)
- Append-only stores fail because old and new versions coexist and the agent must guess which is current; semantic search over episodic logs lets a recent passing mention outrank the relevant older session. — [The Nuanced Perspective](https://thenuancedperspective.substack.com/p/designing-agentic-memory-in-2026)
- Ground Truth First evaluates per-fact validity intervals, sent/received trust distinctions, and as-of-date questions, and finds the provenance-typed graph is what holds up at nine weeks. — [arXiv 2607.21962](https://arxiv.org/abs/2607.21962)

**Forgetting and decay**
- Hindsight: exponential decay is a reasonable default; step-function decay for facts invalidated by external events; decay tuned too aggressively loses stable facts like a user's name, too loosely keeps stale state; "add decay only when the agent tracks state changes"; "evict only for compliance" (GDPR, user deletion, PII), with archival tiering (Letta core/archival) and TTL/LRU as the other eviction cases. — [Hindsight consolidation post](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)
- MemoryAgentBench: most systems fail selective forgetting; only it tests forgetting at all. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)
- Per-memory perishability / type-conditioned decay (Scrub Jay), Weibull decay (SSGM), budget-aware Priority Decay (FiFA): forgetting as reduced accessibility, not deletion (Oblivion). — [arXiv 2608.04746](https://arxiv.org/pdf/2608.04746); [arXiv 2603.11768](https://arxiv.org/pdf/2603.11768); [arXiv 2606.30306](https://arxiv.org/pdf/2606.30306)
- Machine unlearning is "not yet production-ready"; deletion must be executed across every tier. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)

**Provenance, scoping, governance**
- MemClaw primitives: scoped retrieval, temporal supersession, provenance tracking, policy-governed propagation; depth-four derivation chains reconstructed 100% with writer identity; tenant isolation held but sub-tenant scope was initially bypassed on direct GET-by-id. — [arXiv 2606.24535](https://arxiv.org/abs/2606.24535)
- Graphiti keeps raw episodes as non-lossy provenance for every extracted fact. — [Graphiti docs](https://help.getzep.com/graphiti/getting-started/overview)
- Mem0 scopes by `user_id`, `agent_id`, `run_id`/`session_id`, `app_id`/`org_id`. — [Mem0 State of Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Forcepoint-style poisoning defense: store each memory with source, source type, user-confirmed flag, and risk score (via vendor article). — [Vectorize, memory poisoning](https://vectorize.io/articles/ai-memory-poisoning)
- Governed collaborative memory should be judged on provenance fidelity and correction pathways, not only recall. — [arXiv 2605.04264](https://arxiv.org/abs/2605.04264)
- Privacy: encryption, per-user scoping, PII redaction, deletion across every tier. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)

**Evals and observability**
- Survey: operation logging, replay tools, "memory diffs", regression tests for embedding changes. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)
- Hindsight production metrics: per-turn retrieval count and token usage, entity-resolution merge rate, fact-invalidation events, retrieval cache hit rate; per-turn token cost climbing linearly with session count signals noise accumulation; evaluation methods: multi-session reasoning accuracy, synthetic contradiction tests (inject state change, query current state later), per-turn token cost trends. — [Hindsight consolidation post](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)
- CoreDotToday checklist: full-context baseline with same answering model; test the grader with deliberately wrong/hedged/near-date answers; audit the answer key once with a strong model (under one cent per question); compute minimum detectable difference; build small tests on your own tasks (knowledge updates, point-in-time); publish answering model, grading model, prompt, dropped questions, CI, baseline, cost, latency. — [braindetox synthesis](https://braindetox.kr/en/posts/memory_benchmark_scores_reliability_2026.html)
- Hindsight's four-question checklist for evaluating any memory system: what becomes a memory; how does it know two facts concern the same thing; how does confidence in old facts degrade; when and why does a memory leave; "the LLM decides at write time" or "we don't model that" are warning signs. — [Hindsight consolidation post](https://hindsight.vectorize.io/blog/2026/05/21/agent-memory-consolidation)
- Systems paper recommendations cover construction scheduling, capability floors, amortizing construction cost via query volume, freshness-latency trade-offs, fleet-scale management. — [arXiv 2606.06448](https://arxiv.org/abs/2606.06448)

**Pragmatic baselines**
- Effloow: treat each memory product as "a retrieval component, not a source of truth"; default to pgvector and add specialized memory only when it beats that baseline on your workload. — [Effloow](https://effloow.com/articles/mem0-zep-letta-agent-memory-latency-benchmark-2026)
- Letta: agent tool-use ability matters more than the retrieval mechanism; simpler tools get used better. — [Letta, Aug 2025](https://www.letta.com/blog/benchmarking-ai-agent-memory)
- Survey: start with Pattern B (context + retrieval store), instrument heavily, graduate to learned control only when data justifies it. — [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)

### Inferences
- A provider-agnostic layer that satisfies the 2026 consensus needs, at minimum: an append-only episode log (provenance), an extracted-fact/entity layer with bi-temporal validity and explicit invalidation, write-time entity resolution and dedup with the contradiction check ordered before the dedup gate, scoped multi-tenant reads enforced on every access path, a pluggable extraction model recorded per fact, and an eval harness that runs operation-level checks (HaluMem-style) plus a full-context baseline. Decay and eviction should be configurable and off by default except for compliance deletion.
- Because frontier models now read long contexts well, the layer should also offer a "raw history + search tools" access mode (grep/search over episodes) alongside structured recall, so the answering model can fall back to agentic retrieval when extraction is wrong.

### Gaps
- No source quantified the production cost of entity resolution at write time versus query time beyond qualitative statements.
- No independent data on how often write-time contradiction detectors fire correctly in production (YantrikDB's author admitted theirs "needs work to actually fire on raw text").
- GDPR/right-to-erasure handling across tiers (vectors, graph edges, summaries, caches) is named as mandatory by multiple sources but no reference implementation or audit was found.
