# Existing open-source / self-hostable memory-layer projects for LLM apps and agents (state as of 2026-10-23)

Method note: GitHub star counts, licenses, last-push dates and latest releases below were pulled directly from the GitHub REST API (`api.github.com/repos/<owner>/<repo>` and `/releases`) on 2026-10-23 unless otherwise stated. Qualitative claims come from each project's README/docs or from cited third-party write-ups. Most published benchmark numbers are vendor self-reported and flagged as such.

## Key Question 1: Which are the leading projects, and what does each one look like (license, maturity, architecture, backends, providers, exposure, multi-tenancy, deployment)?

### Takeaway
The field has split into five rough tiers: (a) large VC-backed open-core "memory API" products (Mem0, Supermemory, Zep/Graphiti, Cognee, Hindsight, Memori, MemOS, EverOS, OpenViking); (b) agent-runtime products where memory is a byproduct (Letta); (c) small AGPL/Apache memory servers with a hosted option (Honcho, basic-memory, Memobase); (d) libraries without a server (LangMem); and (e) MCP-only "memory servers" (reference MCP memory server, mcp-memory-service, LongMemory). Memary is effectively abandoned (last push Oct 2024), Zep Community Edition is deprecated (Apr 2025), and Letta's Docker server surface is marked "no longer actively maintained" in 2026.

#### Mem0 (and OpenMemory)

- Self-hosted server: `cd server && make bootstrap` or `docker compose up -d`; dashboard at localhost:3000; "Auth is on by default"; `AUTH_DISABLED=true` only for local dev — [Mem0 README](https://github.com/mem0ai/mem0)
- Self-hosted server docs: "A Docker stack with a dashboard, per-user API keys, and a request audit log"; default vector store "Postgres + pgvector"; bundled LLM providers `openai`, `anthropic`, `gemini` — [Mem0 self-hosted overview](https://docs.mem0.ai/self-hosted/overview)

- Zep blog (Apr 2, 2025): "we've decided to stop maintaining and releasing Zep Community Edition"; repo stays Apache 2.0 but "we will no longer provide updates or active support"; open-source focus moves to Graphiti; reason given: open-core "wasn't aligning well with our team's actual capabilities and values" — [Zep blog](https://www.getzep.com/blog/announcing-a-new-direction-for-zeps-open-source-strategy/)

### Inferences
- Star counts are a weak maturity signal in this category: Hindsight went from zero to ~53k stars in under 12 months, while Memary (2.7k, HN-famous in 2024) is dead; weighting last-push date and release cadence matters more.
- The "self-hostable" label is eroding at the top of the market: Zep CE (2025), Letta's Docker server (2026) and Supermemory's closed-source binary mean three of the best-known names are no longer fully open self-hosted servers. ## Key Question 2: Which are production-ready self-hosted (auth, multi-tenancy, backups, observability, scaling) versus demos/libraries?

### Takeaway
Only a handful ship auth + tenant isolation + a scalable deployment story in the open-source artifact: Hindsight (Helm, banks, tenant config), Cognee (multi-tenant auth default, Docker Compose, deploy templates), Mem0 OSS server (auth on by default, per-user API keys, audit log, but no orgs/projects), Honcho (workspaces + JWT, auth off by default), MemOS (Docker Compose, user isolation), OpenViking (accounts + isolation). Graphiti's servers, LangMem, the reference MCP memory server and Memary are explicitly libraries/demos.

### Cited Findings
- Hindsight: Docker, Docker Compose, Kubernetes via Helm, bare-metal pip; banks are isolated stores with "no cross-bank leakage"; hierarchical config "global, per-tenant, per-bank"; tenant/auth/storage extension points; backups and SLA mentioned only for Hindsight Cloud — [Hindsight README](https://github.com/vectorize-io/hindsight)
- Cognee: "the API defaults to multi-tenant mode and every /api/v1 call requires an authenticated user"; Docker image and Compose; `distributed/deploy/` templates; but Postgres-as-graph is "a demo feature" and production Postgres graph requires a licensed product — [Cognee README](https://github.com/topoteretes/cognee)
- Mem0 OSS server: "Auth is on by default"; "dashboard, per-user API keys, and a request audit log"; but "No org/project concept; a single local config" and no graph or Dream — [Mem0 README](https://github.com/mem0ai/mem0); [Mem0 Platform vs OSS](https://docs.mem0.ai/platform/platform-vs-oss)

### Inferences
- No open-source project documents backups or observability as a first-class self-hosted feature; backups are universally delegated to the underlying Postgres/Neo4j, and "observability" appears only as dashboards/audit logs (Mem0) or Cloud SLAs (Hindsight).
- Horizontal scaling is only credibly addressed by Hindsight (Helm chart) and Cognee (distributed deploy templates); everyone else documents single-node Docker Compose.
- Honcho and Graphiti ship with auth off/absent by default, which is a footgun for teams that `docker compose up` and expose a port.

## Key Question 3: Which work across providers in practice (Claude, Gemini, OpenAI, Ollama) and how do they attach (SDK, MCP, extension, proxy)?

### Takeaway
Almost every project claims provider-agnosticism via OpenAI-compatible endpoints, but defaults are OpenAI everywhere (Mem0 gpt-5-mini, Graphiti, Honcho gpt-5.4-mini, Cognee) and several note hard requirements (structured output, tool calling) that hurt small local models. Attachment is converging on MCP for coding tools (Claude Code, Cursor, Codex) plus per-app SDKs; only Hindsight documents a client-wrapper that intercepts OpenAI/Anthropic calls, and no project surveyed ships a true OpenAI-compatible HTTP proxy.

### Cited Findings
- Mem0: default `gpt-5-mini`; server bundles `openai`, `anthropic`, `gemini`; README says "supports other LLMs" via separate page — [Mem0 README](https://github.com/mem0ai/mem0); [Mem0 self-hosted overview](https://docs.mem0.ai/self-hosted/overview); attach: Python/TS SDK, CLI, REST, hosted MCP at `mcp.mem0.ai/mcp`, OpenCode/Pi plugins (buggy per issues #6003, #7602, #7559), Chrome extension — [mem0-mcp](https://github.com/mem0ai/mem0-mcp); [issue search](https://api.github.com/search/issues?q=repo:mem0ai/mem0+is:issue+is:open+sort:reactions-%2B1-desc)
- Graphiti: OpenAI default; Anthropic/Gemini/Groq extras; Ollama via OpenAI-compatible endpoint; "works best with LLM services that support Structured Output" — [Graphiti README](https://github.com/getzep/graphiti)
- Honcho: "Every feature defaults to openai / gpt-5.4-mini"; OpenRouter/OpenAI-compatible; "Models must support tool calling" — [Honcho README](https://github.com/plastic-labs/honcho)
- Cognee: OpenAI when key set; Ollama supported; GLiNER local-model mode with no key; attach via Claude Code plugin, Codex plugin, OpenClaw plugin, MCP, Python/TS/Rust/REST — [Cognee README](https://github.com/topoteretes/cognee)
- Hindsight: "25+ providers" incl. OpenAI, Anthropic, Gemini, Groq, Bedrock, Ollama, LM Studio, llama.cpp; attach via REST, Python/Node/Go/CLI, per-bank MCP endpoint on by default, and an "LLM Wrapper" that wraps an OpenAI or Anthropic client to add automatic recall/retain — [Hindsight README](https://github.com/vectorize-io/hindsight)

- Letta: OpenAI, Anthropic, Ollama, OpenAI-compatible local providers; Docker servers "require explicit embedding configuration" — [Letta self-hosting docs](https://docs.letta.com/guides/selfhosting); Letta Code claims deployment "across every model provider" — [WebSearch summary of Letta Mar 16, 2026 post](https://docs.letta.com/)
- LangMem: provider-prefixed model strings (`anthropic:`, `openai:`) via LangChain — [LangMem docs](https://langchain-ai.github.io/langmem/)

- Self-hosted extraction quality depends on model size: a community Unraid post on the mem-zero MCP server notes the bundled Qwen2.5-3B gives "basic fact extraction" while "A 7B+ model on GPU produces significantly better extraction" — [Unraid forum](https://forums.unraid.net/topic/198592-support-mem-zero-self-hosted-mcp-memory-server-for-ai-coding-assistants/)

### Inferences
- "Provider-agnostic" in this market usually means "any OpenAI-compatible chat endpoint that supports structured output/tool calling"; Claude and Gemini are first-class in Hindsight, Memori, Supermemory, Mem0 and Graphiti, but Honcho and Cognee route them through OpenAI-compatible shims or do not list them.
- MCP has become the universal attachment for IDE/CLI agents (Claude Code, Cursor, Codex), while web chat apps (ChatGPT, claude.ai, Gemini) can only be reached via browser extensions or ChatGPT Developer Mode/Custom GPT actions.
- The absence of an OpenAI-compatible reverse proxy in any major project is notable; Hindsight's client wrapper and Mem0's SDK are the closest to "transparent" memory injection.

- Did not find hands-on reports of running Mem0, Honcho or Graphiti extraction on Ollama-hosted small models at production quality; only the generic mem-zero anecdote above.
- Supermemory's exact MCP gating for self-hosted vs platform may have changed with server-v0.0.9 (Oct 2026); not re-verified beyond the docs page.

## Key Question 4: What do users complain about (quality, latency, extraction cost, cloud lock-in, open-core limits)?

### Takeaway
Complaints cluster around (1) benchmark credibility and extraction quality (Mem0 numbers failing to reproduce; add-only OSS pipeline leaving stale facts), (2) write-path cost and latency from LLM extraction (1-2 LLM calls per stored turn), (3) open-core gating and vendor pivots (Zep CE, Letta server, Mem0 graph/Dream, Supermemory closed binary), and (4) self-hosting rough edges (stale Docker images, no semver tags, broken plugins). Direct Reddit/HN community threads were sparse; most evidence is from GitHub issues and vendor-neutral or competitor blogs.

### Cited Findings
- Benchmark credibility: "The headline vendor benchmark numbers do not reproduce under a competitor-run harness" — Maximem measured Mem0 at 73.8% LongMemEval vs the 94.4% claim, and "An independent paper measured 49.0%" — [Mnemoverse](https://mnemoverse.com/docs/library/ai-memory-solutions-2026-q3); Zep published "Lies, Damn Lies, & Statistics: Is Mem0 SOTA in Agent Memory?" (May 2025) — [Zep blog via HN](https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)

What ships now is single pass extraction that only ever adds" — [Level Up Coding (Medium)](https://levelup.gitconnected.com/what-actually-happens-when-you-try-to-give-an-agent-a-memory-that-survives-the-session-7b6126ef378b); Mem0 OSS "Removed" graph and "Not available" Dream (which "supersedes outdated facts, and merges duplicates") — [Mem0 Platform vs OSS](https://docs.mem0.ai/platform/platform-vs-oss)

### Inferences
- The loudest "complaint" is epistemic: nearly all accuracy claims are vendor-run on vendor harnesses; Hindsight is the only project claiming independent reproduction (Virginia Tech, Washington Post) and that is itself a vendor claim.
- Open-core pressure is concentrating at exactly the features a serious self-hoster needs (conflict resolution/supersession, graph, orgs/projects), which pushes evaluation toward fully-open projects (Hindsight, Cognee, Honcho, MemOS) or toward building in-house.
- Write-side LLM cost is the hidden operating expense; projects that extract in the background (Memori, Honcho, Letta sleeptime, MemOS MemScheduler) move it off the latency path but not off the bill.

## Key Question 5: Is anything positioned as "one memory shared across ChatGPT, Claude, Gemini, Cursor"? How mature?

### Takeaway
Yes, but it is a browser-extension-and-MCP patchwork: Mem0's OpenMemory Chrome extension (ChatGPT, Claude, Perplexity, Grok, Gemini) is the best-known free option; a dozen small commercial extensions (MemoryPlugin, Vity/Maximem, AI Context Flow, ConvoFlow, Unibase, MemoryX) target the same chat sites; and MCP-side projects (basic-memory, mcp-memory-service, LongMemory, Supermemory, Memori) cover Claude Code/Cursor/Codex but reach ChatGPT only via Developer Mode or Custom GPT actions. None is a mature, self-hosted, single system spanning both web chat and coding agents; Mem0's local OpenMemory MCP server's status is murky after the mem0-mcp repo was archived in Mar 2026.

### Cited Findings
- OpenMemory Chrome extension: sites ChatGPT, Claude, Perplexity, Grok, Gemini; "works entirely in the browser, no server needed"; Claude requires manual `Ctrl+M`; "completely free... No usage caps" — [Mem0 blog](https://mem0.ai/blog/introducing-the-openmemory-chrome-extension); earlier "Show HN: Mem0 Browser Extension: Shared Memory Across ChatGPT, Claude, Perplexity" (Nov 2024, 34 points) — [HN](https://news.ycombinator.com/item?id=42042401)
- OpenMemory MCP (May 2025): Cursor, Claude Desktop, Windsurf, Cline; local Docker server; ChatGPT not a listed client — [AIMultiple](https://research.aimultiple.com/memory-mcp); [Mem0 blog](https://mem0.ai/blog/introducing-openmemory-mcp); `mem0ai/mem0-mcp` archived Mar 24, 2026 pointing to hosted `mcp.mem0.ai/mcp` — [GitHub](https://github.com/mem0ai/mem0-mcp)
- MemoryPlugin: Chrome extension adding long-term memory "to your chats with ChatGPT, Claude, Gemini, and LibreChat" — [Chrome Web Store](https://chromewebstore.google.com/detail/memoryplugin-long-term-me/iaelpdacgkkhecjoojjgkhiengnbjacd)
- Vity (Maximem): one private memory across ChatGPT, Claude, Gemini, Perplexity (page dated Apr 2026) — [Maximem](https://www.maximem.ai/cross-app-memory); AI Context Flow ships as extension (Chrome, Opera, Edge, Brave) and MCP server; ConvoFlow and Unibase Memory save/summarize chats and inject into new sessions — [Vilix roundup](https://vilix.ai/blog/best-universal-ai-memory-extensions); [Plurality roundup](https://plurality.network/blogs/best-universal-ai-memory-extensions-2026/)

### Inferences
- The only path that reaches all four of ChatGPT web, claude.ai, Gemini web and Cursor today is a browser extension plus an MCP server sharing one backend; Mem0 is the only vendor offering both halves, and its local-server half is in flux.
- The cross-app extensions are almost all closed-source freemium SaaS with small teams; none surveyed documents self-hosting of the extension backend except via Mem0's OpenMemory dashboard/server.
- For a self-hosted team, the realistic "shared memory" design is an MCP server (Hindsight/Honcho/Cognee/mcp-memory-service) for coding agents and desktop apps, accepting that web-chat ChatGPT/Gemini are reachable only via Developer Mode/Custom GPT actions or an extension you write yourself.

- Did not confirm current status of the local OpenMemory MCP server (docs page 404; one third-party claim of deprecation).
