# Provider-native AI memory features and memory portability/interoperability (state as of October 2026)

Scope note: "Consumer app" = the provider's own chat assistant (ChatGPT, Claude.ai, Gemini app, Copilot, Grok, Meta AI). "Developer primitive" = something you call from an API/SDK. Each feature claim carries the date reported by its source. Several primary help-center pages (OpenAI help center, Google's blog post, gHacks) returned HTTP 403/404 to the fetch tool; where that happened the claim is attributed to the secondary source actually read and flagged as such.

## KQ1. How do ChatGPT, Claude (app + Claude Code), Gemini, Microsoft Copilot, Grok and Meta AI memory work; what is stored, where, and can it be exported/imported?

### Takeaway
Every major consumer assistant now has persistent cross-chat memory, but none offers a structured, machine-readable export of the *memory layer itself*. The only "portability" that exists in October 2026 is prompt-based: Claude (March 2, 2026) and Gemini (March 26, 2026) ship import tools that ask the user to run a "list everything you remember about me" prompt in the old assistant and paste the plain-text output into the new one. Chat-history exports (ZIP/JSON) exist everywhere, but they are not the memory.

### Cited Findings

**ChatGPT (OpenAI)**
- OpenAI's help center states saved memories are stored separately from chat history; the "new memory system" updates memories automatically and a legacy "saved memories" mode can be switched back to in Settings > Memory; deleting a saved memory stops its use in personalization but "does not remove mentions of that information from past conversations" — per search-result excerpts of [OpenAI Help: Memory and new controls FAQ](https://help.openai.com/en/articles/8590148-memory-and-new-controls-faq) (page itself returned HTTP 403 to the fetch tool; wording not verified first-hand)
- No dedicated memory export exists. The official Settings > Data Controls > Export Data ZIP contains conversations (conversations.json, chat.html), not the saved-memory entries; the only way to get memories out is copying from "Manage memories" or asking ChatGPT to list them — [MemoryPlugin (vendor, commercial interest)](https://www.memoryplugin.com/tools/chatgpt-memory-export); [memx.app guide](https://memx.app/how-to/how-to-export-your-chatgpt-memory/); [notis.ai](https://www.notis.ai/blog/can-you-export-your-chatgpt-memory/). One guide contradicts this and says memories are included in the account snapshot — [bluehost guide](https://www.bluehost.com/blog/chatgpt-import-memory/). Independent July 2026 test confirms the "conversations only; saved memories can't be exported; not re-importable" position — [Stan Tyan, DEV Community, Jul 16 2026](https://dev.to/stantyan/i-tested-7-ai-memory-products-for-portability-all-7-lock-you-in-31pm)
- Data export can take up to 7 days to arrive and the download link expires after 24 hours; exports are not available from ChatGPT Business/Enterprise workspace settings — [memx.app guide](https://memx.app/how-to/how-to-export-your-chatgpt-memory/); [allainews, Sept 2026](https://allainews.net/can-chatgpt-memories-be-exported-to-another-account/) (secondary; states OpenAI docs say exported conversations do not transfer memories, settings, GPTs or files between accounts)
- OpenAI has no memory *import* feature as of the sources found (no result mentioned one) — gap, see below.

**Claude consumer app (Anthropic)**
- Memory was paid-only from October 2025 until March 2, 2026, when Anthropic opened memory, compaction, file creation, connectors and skills to the free plan and launched a memory import tool at claude.com/import-memory; Anthropic says memory "will remain an option on the free plan" — [MacRumors, Mar 2 2026](https://www.macrumors.com/2026/03/02/anthropic-memory-import-tool/); [9to5Mac, Mar 2 2026](https://9to5mac.com/2026/03/02/free-claude-users-can-now-use-memory-and-import-context-from-rivals/); [Bloomberg, Mar 3 2026](https://www.bloomberg.com/news/articles/2026-03-03/anthropic-tries-to-win-users-from-chatgpt-with-memory-feature)
- Import mechanism (official): run Anthropic's suggested prompt in "your other AI service"; it asks for a single code block with entries formatted "[date saved, if available] - memory content", grouped by category, with a completeness confirmation; users may edit the prompt to drop sensitive items; if the other service can generate files, a Markdown export can be requested instead. Then Settings > Memory > "Start import" > paste > "Add to memory"; Claude "extracts key information and stores it as individual memory entries" reviewable in the memory panel. Available on Free, Pro, Max, Team and Enterprise, web and desktop. Imports are labelled "experimental, and Claude may not always incorporate them successfully." Memory "focuses on work-related topics, so unrelated personal details may not be retained." — [Anthropic Help: Import and export your memory from Claude](https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude)
- Two memory experiences coexist: the new one (Settings > Memory, all plans, import appears "shortly after") and a legacy one (Settings > Capabilities > Memory, a small number of Team/Enterprise orgs) where imports become "memory edits" under "Manage edits" and can take up to 24 hours to appear — [Anthropic Help](https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude)
- Export from Claude (official): "View and edit your memory" under Settings > Capabilities, or ask Claude in chat to write out memories verbatim; save as a local file or paste into another service. No structured/downloadable memory file format is described — [Anthropic Help](https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude). Third-party test: "Account ZIP (JSON); memory exports as a text summary … imports in, no structured export out" — [Stan Tyan, Jul 2026](https://dev.to/stantyan/i-tested-7-ai-memory-products-for-portability-all-7-lock-you-in-31pm)
- Reported import sources: ChatGPT, Gemini, Copilot ([Storyboard18](https://www.storyboard18.com/amp/digital/anthropic-launches-claude-memory-tool-overtakes-chatgpt-in-app-store-91155.htm)); a later guide also lists Grok ([Medium guide](https://medium.com/@unicodeveloper/how-to-import-memory-into-claude-from-chatgpt-gemini-or-grok-step-by-step-guide-c78ac8f7e4a4)). The official article does not enumerate sources.
- The import prompt text quoted in press: "List every memory you have stored about me, as well as any context you've learned about me from past conversations … Output everything in a single code block so I can easily copy it." — [MacRumors](https://www.macrumors.com/2026/03/02/anthropic-memory-import-tool/)

**Claude Code memory (CLAUDE.md + auto memory)** — developer tool, file-based, fully exportable
- Two mechanisms: CLAUDE.md files (human-written instructions) and "auto memory" (notes Claude writes itself). Both are plain Markdown loaded at session start; "Claude treats them as context, not enforced configuration." — [Claude Code docs: How Claude remembers your project](https://code.claude.com/docs/en/memory)
- CLAUDE.md scopes/locations: managed policy (`/Library/Application Support/ClaudeCode/CLAUDE.md` on macOS, `/etc/claude-code/CLAUDE.md` Linux), user (`~/.claude/CLAUDE.md`), project (`./CLAUDE.md` or `./.claude/CLAUDE.md`, shared via source control), local (`./CLAUDE.local.md`, gitignored). `@path` imports (max 4 hops); `.claude/rules/*.md` with optional `paths:` frontmatter; AGENTS.md read in place of CLAUDE.md (v2.1.277+) — [Claude Code docs](https://code.claude.com/docs/en/memory)
- Auto memory: stored at `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index (first 200 lines / 25 KB loaded every session) plus one topic file per memory; four note types recorded in YAML frontmatter (`user`, `feedback`, `project`, `reference`); `modified` ISO-8601 timestamp written by Claude Code; "Auto memory is machine-local … Files are not shared across machines or cloud environments"; relocatable via `autoMemoryDirectory` setting; disable via `autoMemoryEnabled: false` or `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`; "Auto memory files are plain markdown you can edit or delete at any time." — [Claude Code docs](https://code.claude.com/docs/en/memory)
- Cross-tool import: `/init` reads Cursor rules (`.cursor/rules/`, `.cursorrules`), Copilot rules (`.github/copilot-instructions.md`) and, with `CLAUDE_CODE_NEW_INIT=1`, AGENTS.md, `.devin/rules/`, `.windsurf/rules/`, `.clinerules`; `/import` copies another coding agent's config (instruction files, MCP servers, commands, subagents, skills) one-time — [Claude Code docs](https://code.claude.com/docs/en/memory)

**Gemini (Google)**
- March 26, 2026: Gemini gained "Import memory" and chat-history import. Memory import = Gemini supplies a prompt to run in the old app, which "generate[s] a preferences summary" pasted back into Gemini; Google says Gemini "will pick up the same key facts you've shared with other apps." Chat history imports as a ZIP, after which past threads are searchable/continuable — [MacRumors, Mar 26 2026](https://www.macrumors.com/2026/03/26/gemini-import-tool/); [The Decoder, Mar 27 2026](https://the-decoder.com/googles-new-gemini-update-makes-it-easy-to-import-memories-from-chatgpt-and-claude/)
- ZIP limit up to 5 GB; one report adds five uploads/day; images/files generated in the old assistant are not included; Google is renaming "Past Chats" to "Memory" — [The Decoder](https://the-decoder.com/googles-new-gemini-update-makes-it-easy-to-import-memories-from-chatgpt-and-claude/); [gHacks, Mar 31 2026](https://www.ghacks.net/2026/03/31/google-adds-chatgpt-and-claude-import-tools-to-gemini-for-memory-and-chat-history/) (gHacks page returned 403 to fetch; limits taken from search excerpt)
- Regional: the import tools are "not available in the UK, Switzerland, or the EEA" at launch — reported in search excerpts of [MacRumors](https://www.macrumors.com/2026/03/26/gemini-import-tool/)/[gHacks](https://www.ghacks.net/2026/03/31/google-adds-chatgpt-and-claude-import-tools-to-gemini-for-memory-and-chat-history/) coverage (not confirmed first-hand; the fetched MacRumors text did not mention regions)
- Export from Gemini: Google Takeout covers activity; "saved info isn't separately exportable"; Gemini "accepts rival ZIPs, flattened to text" — [Stan Tyan, Jul 2026](https://dev.to/stantyan/i-tested-7-ai-memory-products-for-portability-all-7-lock-you-in-31pm)

**Microsoft Copilot**
- Microsoft 365 Copilot (work): "Memories, which include saved memories, details inferred from chat history and custom instructions, are stored in the user's Exchange mailbox in a hidden folder" and therefore inherit mailbox compliance controls (Customer Lockbox, encryption at rest). Enhanced personalization is on by default at tenant level; admins can turn it off via Graph `enhancedPersonalizationSetting`. Purview retention policies "don't apply to Copilot memory"; no audit log entries for memory actions; admins "can't restrict what type of information is added." Feature is "in preview and subject to change" (doc dated 2026-09-02) — [Microsoft Learn: Manage Copilot personalization and memory](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory)
- Export (admin side): "Admins can use eDiscovery and Microsoft Graph Explorer to search, export, and delete users' memory data" — item class `IPM.Contact`, folder `CopilotMemory`; saved and inferred memories are discoverable; custom instructions are not, but users can export them manually via Settings > Personalization — [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory)
- Retention: saved memories persist until the user deletes them; deleting a chat does not delete memories derived from it; chat-history-derived details are deleted within 7 days if the source chats are deleted, and after 30 days if the control is turned off — [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory)
- Rollout: message-center item MC1158329 (updated Sept 1, 2026) puts GA at mid-September 2026, completing late October 2026; roadmap item 551195 "Copilot Enhanced Memory" (personalization on work data) targets November 2026 — [MC1158329 mirror](https://mc.merill.net/message/MC1158329); [WindowsForum summary](https://windowsforum.com/news/copilot-enhanced-memory-brings-work-data-personalization-in-november-2026.429482/) (secondary)
- Consumer Copilot (personal MSA): memories are viewed by asking "What do you know about me?", added/removed by asking, or wiped via profile > Memory > "Delete all Memory"; turning personalization off "makes Copilot forget its memories"; an optional "Microsoft usage data" toggle pulls Bing/MSN/Edge data into personalization. No memory export/download is described — [Microsoft Support: Copilot privacy controls](https://support.microsoft.com/en-us/microsoft-copilot/microsoft-copilot-privacy-controls)

**Meta AI**

### Inferences
- The two shipped "import" tools (Anthropic and Google) are deliberately asymmetric: they ingest rivals' memory via free-text prompt output but neither provider exposes a structured export of its own memory. The practical interchange format in 2026 is therefore "a Markdown/plain-text list the old model wrote about you," lossy and unverifiable.
- For a team using Claude, Gemini and others side by side, the only provider memory that is already a self-owned, versionable artifact is Claude Code's CLAUDE.md/auto-memory Markdown (and the analogous Cursor/Copilot/AGENTS.md rule files). Consumer-app memory in all six assistants is provider-held.
- Microsoft is the outlier in making memory discoverable through enterprise compliance tooling (eDiscovery/Graph), which gives admins an export path that users of ChatGPT/Gemini/Claude do not have.
- EU/EEA availability is uneven: Grok memory (EU/UK excluded since 2025) and Gemini's import tools (EEA/UK/CH excluded at launch) show regulatory friction, which matters for an EU-based team.

### Gaps
- OpenAI's memory FAQ and blog returned HTTP 403, so exact official wording on whether memories are in the data export could not be verified; third-party sources conflict (most say no).
- No source described the internal structure of Claude's consumer memory (e.g., project-scoped memory, memory summary, incognito chats) in enough detail to cite; those details should be verified against Anthropic's "Using memory" help article (URL attempted returned 404).
- Google's own blog post for the Gemini import tools was not retrievable; EEA/UK exclusion rests on search excerpts of secondary coverage.
- No 2026-dated primary source on Meta AI memory changes was found; status is assumed unchanged since Jan 2025.
- No source documented any OpenAI, Microsoft, xAI or Meta memory *import* feature.

## KQ2. Do providers offer memory as an API primitive for developers, and how provider-specific are they?

### Takeaway
Three distinct developer primitives exist: Anthropic's client-side memory tool (you own the store; file-operation protocol), OpenAI's server-side conversation state (Responses `previous_response_id` and Conversations objects, no cross-conversation user memory), and Google's managed Vertex AI Agent Engine Memory Bank (server-side extracted memories in GCP). All three are proprietary in interface; only Anthropic's puts the data on infrastructure you control by design.

### Cited Findings

**Anthropic memory tool + context management**
- "The memory tool operates client-side: Claude requests file operations, and your application runs them. You control where and how the data is stored through your own infrastructure." Tool type `memory_20250818`, name `memory`; commands `view`, `create`, `str_replace`, `insert`, `delete`, `rename` under a `/memories` prefix that "your handler maps onto real storage, such as a per-user directory or keys in a database." Available on all Claude 4 and later models; the API auto-injects a memory protocol system prompt. SDK helpers: `BetaAbstractMemoryTool` (Python, C#), `betaMemoryTool` (TypeScript), `BetaMemoryToolHandler` (Java), and a ready-made `BetaLocalFilesystemMemoryTool`. Docs state "the memory tool itself doesn't require a beta header" (helpers live in beta namespace) — [Claude Platform docs: Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)
- Launched in beta Sept 29, 2025 alongside context editing (`clear_tool_uses_20250919`), both behind beta header `context-management-2025-06-27`; works on Claude API, Amazon Bedrock and Google Cloud Vertex AI — [Thomas Wiegold guide](https://thomas-wiegold.com/blog/claude-api-memory-tool-guide/); [Supermemory docs](https://supermemory.ai/docs/integrations/claude-memory); [Claude docs: Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing). (Note the conflict: current official docs say no beta header is required for the tool; older third-party guides say the header is required. Treat the official page as current.)
- Anthropic recommends server-side compaction over SDK compaction and pairing memory with compaction for long-running agents — [Claude docs: Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool); [Claude docs: Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)
- Reported effect: memory tooling improved agent performance 39% over baseline; context editing alone cut token use 84% in a 100-turn evaluation — as cited by [Activant Research, Aug 12 2026](https://www.activantcapital.com/research/the-memory-moat) (secondary citation of Anthropic figures)

**OpenAI Responses API state**
- Conversation state options: resend history manually (`store: false` to avoid saving); chain with `previous_response_id` ("all previous input tokens for responses in the chain are billed as input tokens"); or create a Conversation object and pass its ID in `conversation`, reusable "across sessions, devices, or jobs." "Response objects are saved for 30 days by default"; Conversation objects and their items are not subject to the 30-day TTL. The page "doesn't describe any user-level or cross-conversation memory primitive" — [OpenAI docs: Conversation state](https://developers.openai.com/docs/guides/conversation-state)
- Conversations can be edited to delete older messages, which `previous_response_id` chains cannot — [OpenAI community announcement](https://community.openai.com/t/new-responses-api-feature-conversation-state-api-thread-like-replacement/1353886) (informal)

**Google Vertex AI Agent Engine Memory Bank**
- Public preview announced July 8, 2025 as a managed service inside Vertex AI Agent Engine; a Gemini model extracts facts/preferences from session history and "can consolidate it with existing memories, resolving contradictions" — [Virtualization Review, Jul 9 2025](https://virtualizationreview.com/articles/2025/07/09/googles-vertex-ai-memory-bank-and-the-industry-shift-to-persistent-context.aspx); [MarkTechPost, Jul 10 2025](https://www.marktechpost.com/2025/07/10/google-ai-releases-vertex-ai-memory-bank-enabling-persistent-agent-conversations/)
- Official overview (page updated 2026-10-22): "store long-term user preferences and facts"; "uses Generative AI models to generate memories"; API quickstart and ADK quickstart; memory revisions can be inspected; IAM Conditions control access; supports VPC-SC, CMEK, data residency at rest, HIPAA, Access Transparency/Approval; GA/preview status is not stated on the page — [Google Cloud docs: Memory Bank overview](https://docs.cloud.google.com/agent-builder/agent-engine/memory-bank/overview)
- A Memory Bank tab in the Cloud Console lists all memories for an agent — [Google Developer Forums](https://discuss.google.dev/t/new-memory-bank-ui-is-now-available-in-vertex-ai-agent-engine/264765); pricing reported by one third-party guide at $0.25 per 1,000 stored memories (unverified) — [UI Bakery](https://uibakery.io/blog/vertex-ai-agent-builder)
- Gemini context caching was not covered by sources retrieved; it is a prompt-cost primitive, not cross-session memory — gap.

**Microsoft / xAI / Meta developer primitives**
- Microsoft exposes tenant memory control via Graph `enhancedPersonalizationSetting` and export via eDiscovery, but no first-party "memory API" for developers was found — [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory). No developer memory primitive from xAI or Meta was found in any source.

### Inferences
- Anthropic's design (model emits file ops; you persist them) is the easiest to back with a shared self-hosted store and is the only one of the three that is provider-agnostic in storage; but the *protocol* (tool name/commands/system-prompt injection) is Anthropic-specific, so a shared store must still be surfaced to Gemini/OpenAI models via a different mechanism (e.g., MCP tools or manual context injection).
- OpenAI's and Google's primitives keep memory server-side in the provider's cloud; portability requires reading it back out through their APIs and re-ingesting elsewhere, with no standard format.
- For a multi-model team, the memory tool's `/memories` file semantics (Markdown/XML files, path-addressed) and Claude Code's auto-memory Markdown are structurally similar, which suggests a file-based Markdown store is a pragmatic lowest common denominator.

### Gaps
- Vertex Memory Bank GA status, export/list API details and official pricing were not confirmed from the official page.
- No source addressed Gemini API context caching as a memory mechanism in 2026; treat as out of scope unless another researcher covers it.
- Whether Anthropic's hosted Claude.ai memory and the API memory tool share any schema was not documented anywhere found.

## KQ3. What role does MCP play as the cross-provider attachment point; which clients support it; competing protocols?

### Takeaway
MCP is now vendor-neutral in governance (donated to the Linux Foundation's Agentic AI Foundation on Dec 9, 2025, co-founded by Anthropic, Block and OpenAI) and is supported by every major client the team cares about (Claude Desktop/Code, ChatGPT, Gemini CLI, Cursor, VS Code Copilot, Windsurf), so a single self-hosted memory MCP server is technically reachable from all of them; the caveats are transport (ChatGPT only reaches remote HTTP/SSE servers) and plan gating. A2A, OpenAI's Apps SDK and Gemini CLI extensions are layered on or beside MCP rather than replacing it.

### Cited Findings
- Dec 9, 2025: Anthropic donated MCP to the Agentic AI Foundation, "a directed fund under the Linux Foundation," co-founded with Block and OpenAI and supported by Google, Microsoft, AWS, Cloudflare and Bloomberg, to keep MCP "open-source, community-driven and vendor-neutral." Anthropic cited "more than 10,000 active public MCP servers" and adoption by "ChatGPT, Cursor, Gemini, Microsoft Copilot, Visual Studio Code" plus AWS, Cloudflare, Google Cloud and Azure — [Anthropic news](https://anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation); [Linux Foundation press release](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation). Founding projects also included Block's goose and OpenAI's AGENTS.md — [Linux Foundation](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)
- The current MCP spec revision linked from the official site is dated 2026-07-28; the site names Claude, ChatGPT, VS Code and Cursor as supporting clients and now documents "MCP Apps" (interactive apps inside AI clients) — [modelcontextprotocol.io](https://modelcontextprotocol.io/)
- Client support matrix (article published May 13, 2026, updated Oct 20, 2026): Claude Desktop — local stdio + remote HTTP custom connectors + OAuth; free accounts limited to one custom connector. Claude Code — stdio and HTTP; requires paid plan or Console account. ChatGPT — remote servers only (SSE/streaming HTTP), no local stdio, requires Developer Mode on paid plans; write actions prompt for confirmation. Gemini CLI — stdio, SSE, streamable HTTP via `~/.gemini/settings.json`. Cursor — stdio/SSE/HTTP, on free Hobby plan. VS Code (GitHub Copilot) — stdio and remote, free tier, Agent mode only. Windsurf (now Devin Desktop) — stdio/HTTP/SSE with OAuth, free. Copilot Studio — connects agents to MCP servers over streamable HTTP (agent builder, not chat app). Also Zed, Cline, Continue, LibreChat, Cherry Studio, Perplexity (paid custom connectors). Gemini consumer app, Grok and Meta AI are not covered — [ContextBolt: Which AI tools support MCP in 2026](https://contextbolt.com/blog/ai-tools-mcp-support/)
- ChatGPT tiering reported differently elsewhere: full read/write MCP limited to Business/Enterprise/Edu, Pro gets read/fetch only — [DEV Community comparison](https://dev.to/olver_thorarinsson_bcf885/which-ai-can-actually-schedule-your-posts-over-mcp-chatgpt-claude-cursor-gemini-cli-and-vs-code-33f5) (conflicts with ContextBolt; treat exact tier rules as unverified)
- Proof of a single memory MCP server serving multiple clients: Mem0's OpenMemory MCP (May 13, 2025) is "a private, local-first memory server that creates a shared, persistent memory layer for your MCP-compatible tools … runs entirely on your machine"; exposes `add_memories`, `search_memory`, `list_memories`, `delete_all_memories`; example: "Store context in Cursor and retrieve it later in Claude or Windsurf" — [Mem0 blog](https://mem0.ai/blog/introducing-openmemory-mcp); [Mem0 docs](https://docs.mem0.ai/openmemory)
- Competing/adjacent protocols: Google donated A2A (Agent2Agent) to the Linux Foundation in June 2025; A2A "complements" MCP (agent-to-agent vs agent-to-tool) — [SD Times, Jun 27 2025](https://sdtimes.com/ai/this-week-in-ai-dev-tools-a2a-donated-to-linux-foundation-openai-adds-deep-research-to-api-and-more-june-27-2025/). OpenAI Apps SDK (DevDay Oct 6, 2025) lets MCP servers ship interactive widgets rendered inside ChatGPT; it started as a rival UI layer to MCP Apps and the two "ended up layered" — [mcp.directory blog](https://mcp.directory/blog/mcp-apps-standard-vs-openai-apps-sdk-2026). Gemini CLI extensions bundle MCP servers plus a "playbook" — [SD Times coverage](https://sdtimes.com/author/jennifer-sargent/page/2)
- OpenAI's AGENTS.md (instruction-file convention) is now a Linux Foundation project and Claude Code reads it natively (v2.1.277+), making repo-level instruction memory the one piece that is already cross-vendor — [Linux Foundation](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation); [Claude Code docs](https://code.claude.com/docs/en/memory)

### Inferences
- MCP is the only attachment point that reaches Claude, ChatGPT and Gemini (CLI) simultaneously; a self-hosted memory server should expose remote streamable HTTP with OAuth to satisfy ChatGPT's remote-only requirement, while local stdio is sufficient for Claude Code/Cursor/VS Code.
- MCP standardizes *access* to memory (tools, resources) but not memory *content*; two clients hitting the same MCP server will still write differently shaped memories unless the server enforces a schema. Content-level standards (KQ4) remain open.
- The Gemini consumer app's MCP support is undocumented in the sources; the Gemini *CLI* is the reliable Google-side MCP client.

### Gaps
- The official MCP "clients" compatibility page was not retrievable (the fetch returned the site home page); the matrix relies on a third-party roundup.
- No source confirmed MCP support in the Gemini consumer app, Grok or Meta AI.
- ChatGPT plan gating for MCP write access is contradictory across sources.

## KQ4. Emerging standards or proposals for a portable memory format / memory interchange; regulatory pressure

### Takeaway
At least five competing open proposals appeared in 2026 (MacPaw Portable Memory `.mem`, Open Memory Protocol, Memory Interchange Format, Portable AI Memory JSON, the IETF draft `draft-saihm-memory-protocol` referenced by a new W3C Community Group), plus an arXiv provenance-verified transfer protocol. None is adopted by any major provider, and none has multiple independent implementations. Regulatory pressure is real but indirect: GDPR Art. 20 portability, the EU Data Act's switching rules (switching fees banned from Jan 12, 2027) and the AI Act are cited by proposals, but no regulator has ruled that chatbot memory is covered.

### Cited Findings
- MacPaw Research "Portable Memory" (preprint, July 6, 2026; Kryvoblotskyi, Stulova, Hamolia): a self-contained `.mem` bundle with canonical byte-reproducible serialization, portable deletion tombstones with proof-of-reach ("verifiable deletion is the core integrity guarantee"), optional Ed25519 signing, MIT reference implementations in Python and Swift with a shared conformance fixture, ingest adapters for mem0, ChatGPT and Claude memory, and a four-level conformance program. Authors state it is "not yet independently implemented, neutrally governed, or widely adopted." — [MacPaw Research](https://research.macpaw.com/publications/portable-memory); [GitHub MacPaw/portable-memory](https://github.com/MacPaw/portable-memory). Described elsewhere as "a plain folder of JSONL files + a manifest + checksums" — [search summary of GitHub README](https://github.com/MacPaw/portable-memory)
- Open Memory Protocol (OMP): vendor-neutral spec for memory objects, storage format and HTTP API with self-hostable reference server and adapters for Claude (MCP) and Cursor — [GitHub SMJAI/open-memory-protocol](https://github.com/SMJAI/open-memory-protocol)
- Memory Interchange Format (MIF): JSON-LD + Markdown dual format with W3C PROV provenance, bi-temporal tracking, entity relationships, Obsidian-native — [GitHub zircote/MIF](https://github.com/zircote/MIF)
- Portable AI Memory (PAM): consumer-oriented single JSON file "any provider can export to and import from" — [portable-ai-memory.org](https://portable-ai-memory.org/)
- W3C AI Agent Memory Interoperability Community Group: proposed May 18, 2026, launched June 3, 2026, charter v1.0 adopted June 19, 2026; 36 participants; chair Russell Jackson (who also maintains the SAIHM implementation). Goal: memory "portable and verifiable across vendors, models, agent frameworks, and tool ecosystems"; deliverables in 12 months: use-case catalogue, baseline interoperability profile, conformance/test-vector pack, regulatory crosswalk (GDPR Art. 17, EU AI Act, NIST AI RMF). Normatively references IETF `draft-saihm-memory-protocol-01`; the IETF Independent Submission "has concluded" and ISE released it from the queue (July 29, 2026 update). Community Groups publish reports, not W3C Recommendations — [W3C CG page](https://www.w3.org/community/ai-agent-memory-interop/)
- Academic: "Portable Agent Memory: A Protocol for Provenance-Verified Memory Transfer Across Heterogeneous LLM Agents" (arXiv 2605.11032, May 2026) marks mainstream systems such as Mem0 as non-portable and argues portability "will prevent the knowledge lock-in that currently fragments the agent landscape" — [arXiv](https://arxiv.org/html/2605.11032v1)
- Empirical state: of seven memory products tested (ChatGPT, Claude, Claude Tag, Gemini saved info, Cursor, Cognee, ByteRover) all fail "import symmetry"; the two open-source ones (Cognee's COGX export, ByteRover's Markdown tree with git history) preserve the most structure but "only one implementation reads" each format — [Stan Tyan, Jul 16 2026](https://dev.to/stantyan/i-tested-7-ai-memory-products-for-portability-all-7-lock-you-in-31pm)
- Regulation — GDPR Art. 20 gives a right to receive personal data processed by automated means on consent/contract "in a machine-readable format" and transmit it to another controller — [IIPRD, Data Portability and AI](https://www.iiprd.com/?p=14136)
- Regulation — EU Data Act (applies from Sept 12, 2025): switching rights for "data processing services"; providers may charge only direct switching costs until Jan 12, 2027 and "from 12 January 2027 onwards … cannot impose any switching charges"; customers can have "exportable data" and "digital assets" ported to another provider or on-premises; 30-day transition (extendable to 7 months); applies to non-EU providers serving EU customers — [Latham & Watkins](https://www.lw.com/en/insights/2025/08/EU-Data-Act-Significant-New-Switching-Requirements-Due-to-Take-Effect-for-Data-Processing-Services); [Mishcon de Reya](https://www.mishcon.com/news/eu-data-act-what-cloud-service-vendors-need-to-know-about-new-switching-rights). A 2024 analysis argues the Data Act's data-provision duty "in principle also includes data generated by the AI model" but is limited by data-protection, IP and trade-secret carve-outs — [Wolf Theiss](https://wolftheiss.com/app/uploads/2024/07/24_07_17_Data-access-rules-as-the-backbone-of-AI.pdf)
- Commentary links the Data Act's Jan 2027 fee ban to weakening memory lock-in — [Cyril Simonnet Substack](https://cyrilsimonnet.substack.com/p/the-memory-moat-works-until-your); [usewire](https://usewire.io/blog/ai-memory-lock-in-blocks-your-own-product/) (opinion)
- Solid pods / personal data stores: no source retrieved connected Solid or PDS projects to AI memory portability in 2026 — gap.

### Inferences
- The field is pre-standard and fragmented: five formats in six months, each with a single implementer. A team choosing a self-hosted store today should pick a trivially convertible internal representation (Markdown/JSONL with provenance and timestamps) rather than betting on any one proposal.
- Deletion propagation ("tombstones", GDPR Art. 17 erasure) is the common design concern across MacPaw, the W3C CG and the arXiv paper, suggesting any shared memory layer should log deletions, not just facts.
- Regulatory leverage is strongest for enterprise/API contexts (Data Act "data processing services") and weakest for consumer chat memory, where no guidance exists yet.

### Gaps
- No EDPB or Commission guidance on whether chatbot memory is "personal data processed by automated means" for Art. 20 or an "exportable data/digital asset" under the Data Act was found.
- No evidence any major provider participates in the W3C CG, MacPaw, OMP, MIF or PAM efforts.
- Solid/personal-data-store angle not covered by any retrieved source.

## KQ5. Discourse on vendor lock-in through memory; quotes and evidence of switching costs

### Takeaway
Analysts and executives broadly agree memory is becoming the primary switching cost in AI ("one of the last real switching costs in enterprise software"), with Altman promising "infinite, perfect memory" and Ben Thompson calling even basic memory "the sort of product feature that can build a moat." The counter-current is that memory layers (Mem0 etc.) are moving the record into customer-owned databases, and that provider import tools (Claude, Gemini) show the labs themselves treating rivals' memory as capturable.

### Cited Findings
- Sam Altman (Dec 22, 2025 interview): AI "is definitely gonna be able to" remember "every word you've ever said in your life"; described building "infinite, perfect memory"; a future device should be "understanding your whole life, your context, everything going on around you." Interviewer Alex Kantrowitz: "the switching cost to leave ChatGPT could be extremely high … With memory, ChatGPT could have a lock in." — [CMSWire](https://www.cmswire.com/digital-experience/i-spoke-with-sam-altman-what-openais-future-actually-looks-like/)
- Ben Thompson (Stratechery, Apr 14, 2025): "ChatGPT's memory feature is pretty basic, but it's the sort of product feature that can build a moat" — [Stratechery](https://stratechery.com/2025/chatgpt-memory-boundaries-and-ai-companions-auren/) (rest paywalled)
- Activant Research (Scott Watson, Aug 12, 2026): "Accumulated memory is, in our view, one of the last real switching costs in enterprise software"; memory layers are shifting the record into customer-owned databases ("The application still runs the workflow. It no longer holds the record"); "Compression is what gets this layer bought in 2026. Ownership is what keeps it bought in 2030"; the thesis breaks if "a lab shipping fully portable, cross-vendor memory" happens. Also cites Mem0 at 41,000 GitHub stars at Series A — [Activant Research](https://www.activantcapital.com/research/the-memory-moat)
- Stan Tyan (Jul 2026): "AI memory portability, as a practical capability, does not exist in July 2026"; "Starting over is the migration plan"; "A format that only one product writes is not portability"; "memory is the new vendor lock-in, memory portability is the architectural decision of the decade" — [DEV Community](https://dev.to/stantyan/i-tested-7-ai-memory-products-for-portability-all-7-lock-you-in-31pm); [stantyan.com](https://stantyan.com/blog/portable-ai-memory-or-permanent-lock-in/)
- MacPaw Research: memory is "the most personal dataset a person delegates to software" and is "locked inside each vendor's proprietary storage" — [MacPaw Research](https://research.macpaw.com/publications/portable-memory)
- Oliver Wyman research (as summarized): accumulated agent memory is "one of the most consequential sources of switching cost"; only 23% of at-scale programs keep most of that record in a neutral schema — [The CTO Advisor, Oct 10 2026](https://thectoadvisor.com/blog/2026/10/10/when-memory-becomes-the-operating-model/) (secondary summary; original Oliver Wyman report not retrieved)
- Enterprise survey: 46% of enterprises call integration/lock-in their top agentic-AI blocker — [AgentMarketCap, Jul 13 2026](https://agentmarketcap.ai/blog/2026/07/13/vendor-lock-in-trap-agentic-ai-46-percent-enterprise-blocker) (vendor-adjacent; methodology not verified)
- David Schatsky: switching costs are "not yet a major factor for consumers" since people move between chatbots easily; reads OpenAI's Pulse as an attempt to build the moat — [Unfolding AI Substack](https://unfoldingai.substack.com/p/do-ai-companies-have-moats)
- Analysts frame ChatGPT memory as "a classic personalization lock-in mechanism" whose accumulated context "doesn't transfer to Claude or Gemini when you leave" — [MindStudio](https://www.mindstudio.ai/blog/ecosystem-strategy-claude-chatgpt-gemini-feature-releases); "what looks like a moat to a business can mean lock-in for users … there is no easy way to extract it" — [Who Controls the Context? Substack](https://mbsamuel.substack.com/p/who-controls-the-context); privacy/filter-bubble concerns — [Parmy Olson via BizNews](https://www.biznews.com/news/chatgpt-personalisation-or-peril-parmy-olson)
- Evidence of competitive switching behavior: Anthropic launched memory import "aimed at people switching from ChatGPT" as Claude hit #1 on the US App Store free chart (Mar 2026) — [Storyboard18](https://www.storyboard18.com/amp/digital/anthropic-launches-claude-memory-tool-overtakes-chatgpt-in-app-store-91155.htm); [Bloomberg](https://www.bloomberg.com/news/articles/2026-03-03/anthropic-tries-to-win-users-from-chatgpt-with-memory-feature); Google followed within 24 days — [MacRumors](https://www.macrumors.com/2026/03/26/gemini-import-tool/)

### Inferences
- The "whoever knows you best wins" thesis is held by both sides: incumbents (Altman) build toward total recall; challengers (Anthropic, Google) ship one-way import tools to neutralize it. The exact phrase "knows you best" was not found in any source; the idea is paraphrased across the cited pieces.
- The March 2026 import race is itself evidence that providers regard memory as a switching cost worth attacking, but every tool is import-only, so the net effect is to re-lock the user in a new silo.
- For an organization, the enterprise-side literature (Activant, Oliver Wyman) argues the durable answer is holding the record in a customer-owned database and renting the model, which is precisely the self-hosted shared-memory architecture the team is considering.
